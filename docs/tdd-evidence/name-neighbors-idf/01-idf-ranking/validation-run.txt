# name_neighbors idf ranking — real-corpus validation

Not filed as an issue. This is the "Site 1" item recorded on issue #517:
https://github.com/Muhanad-husn/axial/issues/517#issuecomment-5132701921

**Command:** `uv run python data/logs/2026-07-30-name-neighbors-idf/before_after.py`
(run from the worktree with `data/` junctioned to `D:/axial/data`; read-only,
zero model calls, zero cost).

**What it does:** loads `_answers_index` and `_name_page_index` ONCE
(225.1s + 60.6s), then computes both the OLD ranking (raw `shared_note_count`
descending) and the NEW ranking (`shared_note_count * idf` descending) for 10
anchors off that one in-memory load — avoiding the ~140s-per-call cost
`name_neighbors` pays for a fresh process (issue #520 item 7, out of scope
here).

## Counts

- Vault: 49,674 name pages, 6,148 prose notes.
- `N` (prose notes carrying a `names` answer at all) = **6,110** (38 of the
  6,148 carry an empty `names: []`).
- `member_count` distribution over the 49,674 pages: max 962 (`Syria`), p99
  25, p90 4, p75 2, median 1 (65.7% of all pages have `member_count == 1`).
- Anchors (member_count in parens), chosen to span that distribution:
  `Syria` (962, hub), `United States` (903, hub), `Michael Mann` (377,
  hub-ish scholar), `Kalyvas` (30, mid), `Idlib` (30, mid), `Al-Azhar` (4,
  ~p90), `Aleppo Vilayet` (4, ~p90), `'Abd al-Salam al-Majali` (2, ~p75),
  `Abeih` (2, ~p75), `Abu Rummannah` (1, median/majority case).
- Degenerate-case guard checked directly against the real corpus: 0 of
  49,674 layer canonicals currently have no vault page (`df == 0` does not
  occur on this pin), so `_idf(0, N)` and `_idf(df >= N, N)` were exercised
  by direct call instead — both return finite, non-NaN, non-crashing values
  (`_idf(0, 100) = 4.605`, `_idf(500, 100) = -1.609`, `_idf(5, 0) = 0.0`).

## Result: the fix does what it claims, with one honest exception

Full before/after top-10 lists: `run.jsonl` (one record per anchor);
`console.log` (readable form).

| anchor (member_count) | top-5 displaced (hub → out) | top-5 promoted (specific → in) |
|---|---|---|
| Syria (962) | *(none)* | *(none)* |
| United States (903) | *(none)* | *(none)* |
| Michael Mann (377) | Europe, United Kingdom, France | IEMP model, Fascists, The Dark Side of Democracy |
| Kalyvas (30) | Afghanistan, Algeria | Jeffrey Race, Mozambique |
| Idlib (30) | Syria, Damascus | Raqqa, Hims |
| Al-Azhar (4) | Egypt, Cairo, Islam | Syrian Lands, Qalamun, Rashid Rida |
| Aleppo Vilayet (4) | Damascus, Syria, Beirut, First World War | Jaffa, Tyre, Palmyra, *(a book title)* |
| 'Abd al-Salam al-Majali (2) | Jordan, 'Abd al-Hadi al-Majali, 'Abdallah | 'Ali al-Husri, 'Ali al-Nusur, 'Umar al-Nabulsi |
| Abeih (2) | Beirut, 1860 Massacre | Abdullah al-Bustani, American Board of Commissioners for Foreign Missions |
| Abu Rummannah (1) | Asad | Fourth Regional Congress |

8 of 10 anchors show the claimed effect plainly: a hub name (a bordering
state, a broad period, a common institution) drops out of the top 5 and a
name specific to the anchor — one of the anchor's own concepts, a
co-author, a specific place, a specific person — takes its place. `Idlib`
displacing `Syria` itself, and `Michael Mann` displacing `Europe`/`United
Kingdom`/`France` for his own book titles and models, are the clearest
cases.

**Reported plainly, not worked around:** for the corpus's two biggest hubs
themselves (`Syria`, `United States`), the top 5 does NOT change. Their
highest-count neighbours (`Lebanon`, `Egypt`, `Damascus` for Syria;
`United Kingdom`, `France`, `Japan`/`Germany` for the US) are themselves
all hub-scale names (df in the hundreds), so there is no rarity gradient
among them for idf to invert — internal order shuffles by a few ranks
(e.g. Syria's `Damascus` moves 3rd→2nd) but the same five names remain.
This is the honest, expected limit of a rank-only weighting: it cannot
manufacture specificity where an anchor's own most-frequent neighbours are
genuinely other hubs.

**A second, smaller pattern worth noting**, visible at the two sparsest
anchors (`'Abd al-Salam al-Majali`, `Abu Rummannah`): once `shared_note_count`
is 1 for nearly every neighbour and most of those neighbours also carry
`df == 1`, they tie at the same idf weight (`ln(6110/1) = 8.718`) and the
existing canonical-ascending tie-break decides the order among them — i.e.
alphabetical, not a further specificity signal. Expected given the stated
tie-break rule, not a defect.

## Next steps

None required for this fix — it is scoped to the sort key only, per the
issue. If a future pass wants to also break `Syria`/`United States`-style
ties (anchor's top neighbours all hub-scale), that is a new, separate
design question, not a bug in this change.
