## The 0.5 floor fails its own observable, and no floor fixes the case

Raw cosine of the top 5 vectors, floor ignored:

| query | top 5 (score → surface → canonical) |
|---|---|

| **Ungor** | **0.7752 `Uğur Ümit Üngör`** · 0.7673 `Halil Üngör` · 0.6813 `Unger` · 0.6244 `UNSCOB` · 0.6090 `UN` |
| **AANES** | **0.7062 `Aarts`** · 0.6716 `AANS` · 0.6200 `Aas Rustad` · 0.6140 `Rennes` · 0.6070 `AFAD` |
| Autonomous Administration of North and East Syria | 1.0000 exact · 0.9078 `Autonomous Administration of Northeast Syria (AANS)`→same canonical · 0.7937 `Syrian administration`→Syrian government |
| zzqqx nonexistent scholar | 0.4518 `unnamed scholar` · 0.4436 `Zizya` · 0.4180 `Z.J.` (all cut) |

Two things follow.

**At 0.5, `find_names("AANES")` returns five wrong names** — `Aarts` (a person),
`Aas Rustad` (a person), `Rennes` (a place). Spec §8 P0-2 requires `[]`. The
observable fails as written.

**The only floor that satisfies both stated observables is (0.7062, 0.7752].** A
0.07-wide window, read off exactly two cases. That is the hand-tuned constant the
tripwire names, and #268 already paid three review rounds for one.

**And the AANES premise is false: the corpus holds the entity.**
`Autonomous Administration of North and East Syria` is an exact hit with 2 members,
`kind: institution/group`, and it carries the alias
`Autonomous Administration of Northeast Syria (AANS)`. There is also a *separate*,
fragmented `AANS` node with 1 member that never folded into it. So the honest
answer for "AANES" is that name page — not `[]`, and not `Aarts`. What actually
fails is acronym-to-expansion: MiniLM scores `AANES` against the full phrase
below every piece of lexical noise, because an embedding model is not a string
matcher. That is a name-layer gap (the #460 fragmentation family), demonstrated
here for the first time.

## The graph tools work, and the graph is real

| call | result |

| `get_name('Michael Mann')` | 378 members, all parsed; disagreement over 8 named scholars (Laitin, Trentmann, Poggi, Hall, Schroeder, Haugaard, Smith, Wimmer) |

| `who_argues_against('Charles Tilly')` | 2 notes, `position_of` `bellicist` / `bellicist paradigm` |
| `who_cites('Michael Mann')` | 76 notes |
| `who_argues_against('Michael Mann')` | 26 notes |

`hall-2006` cites `Mann` as both `foil` and `support` from the same note — the
author-stated stance is per citation, not per note, and the tool preserves that.

Determinism held on every repeated call: `find_names`, `get_name` member order and
`who_cites` order were byte-identical across two calls in one process.

## Latency: three cold indexes, ~3.3 minutes, then microseconds

| index | cold | warm |
|---|---:|---:|
| name pages (`coverage_count`) | 37–63 s | — |
| note answers (`name_neighbors` / `who_cites` / `who_argues_against`) | 118 s | 0.10–0.14 s |
| encoder + 78,198 vectors (tier 4 only) | 41 s | ~3 s per query |
| tiers 1–3 | — | 0.00 s |

Each is built once per process. A brief run that touches all three pays ~3.3
minutes before the agentic loop does anything; every later call is effectively
free. Tiers 1–3 never load the encoder, so 14 of these 17 queries cost nothing.
