The system, and where the model actually decides

Nine drawings of one pipeline. The first shows the whole of it; the rest open each place a model is handed a judgment, and show the deterministic code standing on both sides of it.

DeterministicCode. Zero model calls. Same input, same output.
Model callA judgment. The dot marks every one.
GateA blocking check the model cannot reach.
ArtifactPersisted on disk. Resumable, inspectable.

Plate I · the wholeOne corpus, three phases, and the artifacts between them

Phase A reads the books once and writes everything down. Phase B answers a question by walking what A wrote. Phase C assembles a paper out of B's answers. Nothing downstream ever reopens a source: every phase after extraction reads persisted artifacts.

Plate II · Phase AThe ingestion ledger, and the one classification everything downstream shares

Ten stages, with what each one costs and what it leaves on disk. The two expensive rows are stage 6 (once per note) and stage 9 (once per name). Everything else is either free or once per source.

Plate III · agentic passInterrogate — one reading, fourteen open questions, and an explicit right to abstain

The pass that produces everything else. Closed vocabularies return bins; open questions return specifics, and specifics are what two passages can share. The frame's example lists reach the model only after it has answered in its own words, and code never bridges the two fields.

Plate IV · agentic passReconcile — clustering is a hint, the fold needs no model, and every merge is reversible data

Names come out of the corpus and have to meet each other. Three things are deliberately separated here: what a shape rule can decide alone, what a clustering can only suggest, and what actually needs a judgment.

Plate V · agentic passGather — the model never fetches, so it cannot blow the window

For every name big enough to hold an argument, what do the authors gathered there actually disagree about? The budget is a constant in code rather than an instruction in the prompt: a prompt-side budget is a request, a code-side budget is a guarantee.

Plate VI · agentic passThe argument map — reaching a passage by what it argues, not by what it happened to name

Name-keyed retrieval only reaches a passage through a proper noun it mentions. The position layer groups passages that make the same argument, once and offline, so a question can land on the argument directly. Both model passes here are deliberately blind to authorship.

Plate VII · the agentPhase B — a model-driven query agent inside deterministic hard gates

This is the one genuinely agentic loop in the system, and the shape of it is the whole architecture: the model plans and re-queries freely in the middle, and code it cannot reach stands on both sides. A fixed retrieval pipeline was rejected because thin results demand a second look only an agent can decide to take.

What the tools return. Notes, opposition edges and argument-map positions are the destination; a name, a publication year and a source are filters on them. The entry point is find_notes, not a door lookup — a historian's question chains two relations and every name-layer tool walks exactly one.

An empty result is a real answer. A tool that resolved nothing says the phrase it tried and each of its words, so a zero has somewhere to go other than the same query again.

Plate VIII · the second armRetrieval over the argument map — door, landing, corridor, assembly

An opt-in path that replaces the loop in plate VII and nothing else: same lens, same synthesis prompt, same budget, same model. If an answer improves here, the improvement is the substrate rather than a changed prompt.

Plate IX · Phase CAuthorship, and the strangers who measure it

Two halves on two different clocks. The paper is assembled and gated on every run; the system is measured on a sample, by reviewers from a different training lab, and only after a positive control proves the panel is still reading.

The shape all nine share

Every model call in this system is surrounded the same way. Code assembles what the model sees, so a packet cannot overflow and a prompt cannot be talked into fetching more. Code reads what comes back, so an invented handle is dropped rather than repaired and a batch nothing could be parsed from is never recorded as a verdict. And code holds a ledger beside every paid pass, so an interrupted run resumes instead of paying twice.

The model does the judgment. The code holds the line.
