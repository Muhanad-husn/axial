# PRD — Axial: Phase A Corpus Ingestion Pipeline (Syria v1)

**Project:** Axial · **Version:** 2.0 (Phase A v1) · **Status:** Ready to build · **Owner:** Operator (single-operator system)

**Inherits.** This PRD is the Phase-A phase spec under [`specs/CHARTER.md`](CHARTER.md), the product-wide behavioural constitution; its P0 criteria are the substrate-layer instance of the charter's five principles.

**On the name.** *Axial coding* is the grounded-theory move — native to this corpus through Malešević — of relating categories to one another along dimensions. v0 read that as *axes*: fixed lists of values, decided before a book was read, applied to every chunk. v1 reads it as the relating itself. Categories come out of the sources by interrogation, meet each other at shared names, and are related on the page where they meet. The Python package is still `axial`.

**Self-sufficiency note.** This document is the *complete* build specification for Phase A. Everything required to build the pipeline — architecture, pipeline stages, config contracts, the interrogation contract, acceptance criteria, and appendices — is contained here, and a builder should be able to start from this file alone. Its single parent is the behavioural constitution in [`specs/CHARTER.md`](CHARTER.md), which governs *why* the pipeline is built as it is; beyond that one charter it references no external file. Where a decision is genuinely unresolved, it is listed under **Open Questions**; everything else is settled and should be built as written.

**How retired material is marked.** Phase A v1 retires several v0 mechanisms. Nothing is deleted silently. A retired section, criterion, or appendix keeps its number and heading, gains the word **STRUCK** in that heading, and carries a note in this shape:

> **STRUCK (D5).** What is retired, in one clause. Where the replacement lives, or which cleanup owns the deletion.

`D1`–`D16` are the numbered decisions of the Phase A v1 design (`plans/phase-a-v1/README.md`), each of which is carried by real text in this document. A struck item is dead contract: no builder implements it, no test pins it. Removing the code behind a struck item is its own cleanup, tracked separately, so a struck section may still describe machinery that exists on disk today.

## 0. What this is, in one paragraph

Axial is a single-operator pipeline that turns a corpus of born-digital academic sources (PDF and DOCX) into an Obsidian wiki the model wrote by reading. Raw sources stay immutable. Above them sits a layer of two node kinds: **notes**, which are bounded passages of the sources' own prose, and **name pages**, one per thing the corpus talks about — a person, a place, an institution, an event, a movement, a period, a figure, a table. Each note is read once and interrogated with open questions: what is claimed, what the claim ranges over, whose position it is, who it argues against, who it cites, what it names. Notes meet each other at the names they share, and what the authors gathered at a name actually disagree about is written on that name's page. The corpus is ~11 GB / ~120 sources in comparative-historical political sociology, heavily weighted toward Syria and the surrounding literature (Mann, Kalyvas, Brubaker, Hinnebusch, Migdal, Skocpol, Tilly, Wedeen, Malešević). The pipeline is **domain-general in mechanism, Syria-specific in content**: no country-specific logic in code; the domain content is a swappable frame that reaches the model as context and examples, never as a gate.

## 1. Problem statement & context

The value of every downstream research pass depends on one thing: the quality of what enters the knowledge graph at ingestion. A corpus of ~120 sources is small enough that infrastructure is not the constraint — ingestion judgment is.

v0 built the substrate and measured it. The measurement is the reason this document was rewritten. Over 31 sources it produced **18,761 notes, 584 edges, all of them intra-book, and zero prose-to-prose or cross-book connections**. The cause was not corpus sparsity and not a threshold set wrong. The only mechanism that ever minted an edge was the cross-reference pass, which asked one question per note ("does this text say *as Table 3 shows*?") and filtered the answer against that book's own figure list. Its edge set was therefore **bipartite and intra-source by construction**: a note could only ever connect to a table or figure in the same book, so no arrangement of its parameters could have produced a link between two passages, or between two books. Everything else the pipeline produced was **attributes**: values picked off closed lists. An attribute sorts notes into bins. It cannot express a relation, so it cannot be an edge, and a graph whose nodes share a bin is not a graph.

Two problems follow, and v1 addresses both.

1. **Nothing in the pipeline ever asked a question whose answer could be an edge.** Multiple-choice questions return bins. Open questions return specifics — a named person, a cited scholar, a position argued against — and specifics are what two notes can share. The fix is to change the question, not to add a detector.
2. **The unit was too small to answer an open question over.** A claim and the evidence for it usually sit several paragraphs apart. A 1000–3000 character window holds half an argumentative move, so a model reading one is unable to answer half the questions worth asking. The fix is a larger note (D1), not a different chunker.

This PRD covers **Phase A (ingestion) and the wiki layer built on it**. It does not cover the downstream research-paper, format-adaptation, or lens-application phases.

## 2. Goals

1. **Structure-aware ingestion.** Produce notes whose boundaries follow the source's argument — found by a recursive/structural splitter that respects the prose's own separator hierarchy (paragraph → line → sentence → character) within each section — rather than arbitrary fixed-size or page-break splitting. Every note is bounded by construction into the `[3500, 9000]`-character band (D1), so no single unit blows a request deadline or token budget downstream, and every note is large enough to hold a whole argumentative move.
2. **Interrogation, not labelling.** Read every note once and ask it open questions, in the model's own words, grounded only in the passage and its book-level context (D6). Where the passage does not support an answer, the answer is an explicit abstention, not a guess (D7). The domain frame reaches the prompt as examples only, and the free answer is asked for before any example is offered, so the examples cannot capture the answer (D8).
3. **A name index that grew out of the corpus.** Every name the interrogation returned is collected, viewed as a distribution, and merged into a canonical index by a model using clustering as a hint (D10). Nothing in that index was decided before a book was read, and every merge is reversible data.
4. **A wiki layer whose links are written, not detected.** One page per surviving name, written by code, carrying its aliases and its member notes as links (D11). Obsidian reads a link in both directions, so the graph view is populated and traversable, and the whole link layer is regenerable without re-reading a single source.
5. **Cross-book disagreement, stated with its grounds.** For each name, a cheap pass reads the notes gathered there side by side and writes what the authors actually disagree about onto the page (D12), with verbatim quotation available as a separate, narrow step where a disagreement warrants it (D13).
6. **Separation of prose and artifacts.** Tables and figures keep their own retrievable pool, pre-tagged for role. They also become nameable things the interrogation can name like any other entity, so they enter the graph through the same door as everything else.
7. **No human-labelling dependency.** The pipeline runs end to end with no annotator in the loop. Its first-pass quality check is an operator opening the graph view and reading name pages, not a returned spreadsheet.

## 3. Non-goals

Each is excluded deliberately; documenting them prevents scope creep and protects the architecture.

1. **No plugin framework, no multi-tenancy, no arbitrary-user configurability.** "General" means *domain/country portability by swapping the frame* — nothing wider. Building for hypothetical future users is speculative generality and is out of scope.
2. **No OCR / no scanned documents.** Born-digital PDF and DOCX only. Scanned files are rejected at intake. This is a deliberate corpus boundary, not a limitation to work around later.
3. **No local model hosting.** Inference is API-based (OpenRouter, NVIDIA developer APIs). A ~11 GB one-time ingestion does not justify local infrastructure.
4. **No downstream phases (B–E) in this document.** Brief intake, research-paper production, format adaptation, and lens application are separate initiatives. B and C are built and have specs; **D (format adaptation) and E (lens application) are future milestones, not a schedule** — GitHub milestones 1 and 2, no spec and no issues (DEC-63).
5. **~~No full-corpus run until the eval closes.~~ STRUCK (D15, D16).** There is no eval to close: the hand-labelled agreement score measured the layer v1 deletes, and its replacement is deliberately deferred until Reconcile's output exists (§9, §10). The gate this non-goal expressed is retired, and D16 requires the opposite — every stage below extraction re-runs over the whole corpus.
6. **No bottom-up vocabulary discovery over notes.** Clustering has exactly one sanctioned job in this pipeline, and it is narrow: inside Reconcile, over **names**, as a **viewing aid** so merge aggressiveness can be chosen by looking at the distribution rather than guessed (D10). It never runs over note text, it never proposes a category or a tag, and it never decides a merge — the model makes every merge call with clusters as hints, and the output is an alias map a human can read and reverse. Clustering as a vocabulary-discovery mechanism remains out of scope.
7. **No rewrite of Phase B here, and Phase B is expected to be degraded.** `axial brief` and the retrieval path filter on the closed vocabularies this document retires (D4, D9). Rewriting them against name pages is a separate feature and must not be smuggled in. Until that feature lands, `axial brief` is degraded, not working-as-before, and that is the known and accepted cost of the change.
8. **No best-of-N interrogation.** One draw per note. Voting was precision spend on a layer being deleted (D4); if variance turns out to matter it is a config change later, not a design.
9. **No rewriting of any note's prose.** The notes are the sources' own words. Nothing in this pipeline asks a model to replace them. Only frontmatter and name pages are written.
10. **No new chunker.** D1 moves two constants. The recursive/structural mechanism is unchanged.
11. **No web or external lookup during interrogation.** The passage and its book-level context are the only inputs (charter Principle I). The one network read anywhere in the pipeline is the intake-time identifier lookup (§7.13), which reads catalog metadata about the *file* and never the argument.

## 4. Architecture principle

**Mechanism-general, domain-portable-by-frame, single-operator.**

The pipeline stages carry no country-specific logic. What changes between domains is content that reaches the model as **context and examples**, and two files hold it: `config/domains/<domain>/schema.yaml` and `config/domains/<domain>/codebook.yaml`. Porting to another country means writing a new frame; the pipeline code is untouched.

**The frame is not a rulebook (D9).** This is the load-bearing change from v0, and it inverts what the schema was for. v0 treated the schema as a controlled vocabulary with enforcement behind it: an off-list value triggered a bounded correction re-ask, and a value still off-list quarantined the chunk. That machinery existed to keep the tagger inside the lists, and the lists are what produced bins instead of edges (§1). In v1:

- **The frame is prompt context.** The field set, the claim-type list, the scope values, the role-in-argument list, and the theory-school taxonomy are supplied to the interrogation as *examples of the kind of answer being asked for*, after the free answer has been given, and marked as examples in the record (D8, §7.15).
- **No value list is a gate.** There is no off-list validator, no vocabulary re-ask, and no `out_of_vocab` quarantine. An answer that matches no example is the normal case, not an error.
- **One list survives with an operational job:** `config/domains/<domain>/polity_canonical.yaml`, the canonical place/person spelling map. It is a **cleanup aid** — it seeds Reconcile's alias map with spellings already known to fold together (§7.16) — and never a gate. An unmapped name always passes through and is reconciled on its merits, exactly as that file's own header has always said.

What the principle does **not** mean: it is not user-facing flexibility, not a config surface for non-technical users, not an abstraction layer over arbitrary domains. One domain frame ships: Syria.

## 5. System overview — the pipeline

Ten stages, the last optional, each a discrete and independently testable module, with a **source-routing step folded into stage 2** (step 2b below) that classifies every tree block before any later stage consumes it.

| Stage | Runs | Model calls |
|---|---|---|
| 1. Intake (+ holdings check, bibliographic read) | per source | 1 per source |
| 2. Structural extraction, then source routing (2b) | per source | 0, plus a bounded per-block call on flagged apparatus candidates |
| 3. Structural envelope | per source | 1 per source |
| 4. Chunking | per source | 0 |
| 5. Artifact classification & routing | per artifact | 0 |
| 6. **Interrogate** (D6) | per note | 1 per note |
| 7. **Reconcile** (D10) | once over all answers | model merges, clusters are hints |
| 8. **Materialize** (D11) | once over the index | 0 |
| 9. **Gather** (D12) | per name | 1 per name, plus a merge call on a batched name |
| 10. **Pairwise support** (D13) | on demand | 1 per pair |

Stages 1–5 are unchanged from v0. Stages 6 and 7 of v0 — **Tagging** and **Cross-reference** — are struck (D4, D5) and do not appear above; §7.14 and P0-7 carry their struck notes.

1. **Intake.** Accept PDF or DOCX. Verify a real text layer exists; reject scanned / no-text-layer files with a clear, logged message. No OCR path. Sources are supplied by the Google Drive connector (§7.10, P0-11), which streams each file's bytes into intake and applies an English-only language gate to text-layer sources before the expensive extraction begins. A **holdings-completeness check** also runs here, reading the raw text layer already in hand to flag a source that carries only part of the work it names (§7.11, P0-1b). Deterministic pre-processing cleans that text — physical page count, running header and footer stripping — and a single model call then judges what kind of document this is and whether the file covers the extent the document claims. Unlike the text-layer check, it flags and reports only: it never rejects, and a flagged source proceeds unchanged. Intake also reads the source's **author, title and date** from the file itself rather than leaving them to the envelope pass (§7.13, P0-1d). Everything intake learns about the file is written to a persisted **source-metadata record** that survives envelope regeneration (§7.12, P0-1c). Output: validated source + its source-metadata record.
2. **Structural extraction, then source routing.** Run docling to produce a hierarchical tree that separates prose sections from non-text artifacts. If docling fails or produces degenerate output on a source, fall back to Unstructured for that source. At tree-build time, before the tree is persisted, a deterministic, model-free **text-normalization pass** repairs decoding defects in each block's `text` (soft-hyphens, whitespace damage, detached combining marks, known glyph-name leaks — full contract in §7.4) without altering the tree's shape or any block's `label`, `type`, or `order`; because normalization happens here, every downstream pass inherits clean text. This tree is produced once per source, persisted, and reused by every later stage for that source (not re-extracted). Output: structural tree (persisted, text-normalized).
   - **2b. Source routing.** Before any consumer reads the tree, a routing step classifies each tree block by its docling structural `label` (§7.4) and assigns it exactly one of three **routes** — **prose**, **artifact**, or **apparatus** (full contract in §7.8). Only prose-routed blocks reach the chunk stage (stage 4); artifact-routed blocks (tables, figures, captions) go to artifact classification (stage 5); apparatus-routed blocks (TOC / index, endnotes / footnotes, running heads, and reference / citation lists detected by content even when docling labelled them prose) are **dropped** — not chunked, not artifact-noted — and recorded with a reason. This is a *single, shared* classification: every downstream pass consumes the routed result rather than re-deriving the prose/non-prose decision for itself. The router runs over the persisted tree and triggers no re-extraction; it calls **no model for the `label`→route mapping**, its one exception being a single bounded per-block classification of the small set of content-flagged apparatus candidates (§7.8), which clean prose never reaches. Output: a route per block, plus the router-owned skip record for dropped blocks.
3. **Structural-envelope pass.** One API call per source extracts the author's stated thesis, a **reconstructed hierarchical table of contents** (grounded in the source's own printed TOC and detected headings), scope, and stated argument. It reads the source's intro / abstract / conclusion where those headings are present, and **widens to a substantive head-of-tree slice** of the source's prose when they are not — so the model is always grounded in real source text and never asked for a thesis over an empty evidence block, and the extraction is grounded only in the supplied text, never in the title or outside knowledge (§7.3, #201). **The envelope is promoted in v1: it is context for everything below it.** Where v0 fed it to one pass, v1 threads the thesis, scope, stated argument and the chapter the note came from into every interrogation call (§7.15), because a model reading one paragraph of a book it has never seen otherwise has no idea what the book is arguing. Output: envelope (JSON).
4. **Chunking (recursive/structural, deterministic, LLM-independent).** For each prose section, the chunk stage finds boundaries with a **recursive/structural splitter** (#165, #191) — the sole chunk mechanism. It splits along the prose's own separator hierarchy — paragraph (`\n\n`) → line (`\n`) → sentence → character — descending to the next-finer separator only when a piece still exceeds the size band. The mechanism is deterministic and model-free: it calls **no embedding model and no text-generating LLM**. Every chunk is **bounded by construction into a two-sided size band** `[CHUNK_MIN, CHUNK_MAX]` = **`[3500, 9000]` characters (D1)**: the raw breakpoints bound size in neither direction on their own, so a deterministic guard pass wraps boundary detection and enforces the band around it. Below `CHUNK_MIN`, a sub-floor chunk is **merged into a same-section neighbour** — into its same-section *predecessor* where the merged result would still fit within `CHUNK_MAX`, otherwise *forward* into its same-section successor, and kept as-is only when it is the section's sole chunk with no neighbour to absorb it — never across a section boundary and never dropped (§7.8 / P0-4); above `CHUNK_MAX`, a chunk is split at its next-best internal boundary (this is what guarantees no unit blows a request deadline or token budget). A section too large for one request — today up to ~143k characters — is therefore *split* into multiple in-band chunks rather than echoed whole through an API. The detected breakpoints remain the **primary** boundary signal; the guard only enforces the band around them. **The band's rationale is the interrogation, not the vault.** v0 anchored it on what the vault stored (~1–3k characters); v1 anchors it on the unit the questions in §7.15 are answerable over. A claim and the evidence for it usually sit several paragraphs apart, so a 3k window holds half an argumentative move and half the questions come back abstained for want of text rather than for want of an answer. Boundaries still track argumentative shifts, not fixed sizes. The stage reads the **prose-routed** blocks of the persisted structural tree only — apparatus and artifact blocks are removed upstream by the source router (§7.8, step 2b) — and it needs no envelope; its meaningful guarantee is that no generative LLM call sits in the chunk critical path. It writes the chunk records to disk (§7.7) **before any downstream LLM spend**, so note quality is inspectable — the examine step, §7.7 — with zero inference cost. Type-detectable non-prose is dropped by the router by structural `label`, not by this stage; a residual size/garble rule survives only as a **backstop**, and its skips are recorded in the same router-owned skip record (§7.8). A narrow **post-split fragment floor** (§7.8, #193, generalized in #197) runs after the splitter to drop any emitted chunk that is unambiguous non-content boilerplate, recording each drop with its reason. A legitimate long section is split, never skipped, so no real prose is silently dropped. Output: on-disk prose chunks (§7.7), which are the **notes** every later stage reads.
5. **Artifact classification & routing.** This pass is the **sole home** of tables, figures, and captions; it receives exactly the artifact-routed blocks from the source router (§7.8, step 2b) — never raw docling output and never apparatus. **It makes no LLM call (issue #429).** Appendix D's six-way `artifact_role` taxonomy was v1's one remaining closed-vocabulary classification, kept on the stated ground that it was "a routing decision over six values, not a description of an argument" — measurement refuted that: two independent runs over the same source disagreed on the role for 48.5% of artifacts and flipped the keep/discard bit on 13.1% of them, and the artifact record carries no content beyond ids, section and caption, so that role was the pass's entire output. The axis and the classification call are both gone. Each artifact is routed to a separate artifact pool with id/source/section provenance and, when one is present, its attached caption; `retrievable` is decided in code by a rule — caption presence — which predicted the old keep/discard bit far better than the model did (4.7% flip rate on captioned artifacts vs. 19.6% on uncaptioned ones). Output: artifacts in the artifact pool.
6. **Interrogate (D6).** One call per note. The note, its author / title / date, its book's thesis and scope, the chapter and section it came from, and the domain frame go in; a record of open answers comes out (§7.15). The questions ask what the passage is about, what it claims, what it is *doing* in the argument, what the claim ranges over and where it stops holding, whose position it is and who it argues against, every named thing in it, who it cites and whether the citation is support / foil / authority, the mechanism, the evidence, the comparison, what is defined versus used, what is conceded or hedged, and what is assumed. Every answer is given only from the passage, and an unsupported answer is an explicit abstention (D7). The free answer comes first and any nearest example is separate and marked (D8). No web, no external lookup, no reliance on what the model knows about the book (charter Principle I). Output: one answer record per note (§7.15).
7. **Reconcile (D10).** Every name and answer from stage 6 is collected into an inventory, embedded and clustered to produce a **distribution to look at**, and the model then makes the merge calls with the clusters as hints. Merge aggressiveness is chosen by inspection: start loose, tighten by looking. Output: a reversible **alias map** and the surviving name list, which is the index (§7.16).
8. **Materialize (D11).** Code writes the vault. Each note becomes a prose note carrying its interrogation answers as frontmatter; each artifact becomes an artifact note; each surviving name becomes a **name page** carrying the name, its kind, its aliases, and its member notes as links. No model call. Links live in the name pages, not in the notes: Obsidian treats a link as a connection in both directions, so the graph draws identically and the whole link layer is regenerable — a changed Reconcile rewrites a few hundred name pages instead of six thousand notes. Output: the vault (§7.17).
9. **Gather (D12).** For each name, code assembles a fixed packet from its member notes — per note: author, year, the one-sentence claim, whose position, who it argues against, roughly 800 characters — under a **hard character budget enforced in code, not in the prompt**. The model never fetches. A name whose packet exceeds the budget is split into batches, Gather runs per batch, and a short final call merges the batch findings; large names are the interesting ones, so batching is a designed path. The model writes what the authors gathered at this name disagree about, and the result is written onto the name page (§7.18). Output: disagreement text and name-to-name links on the name pages.
10. **Pairwise verbatim support (D13, optional).** Where a disagreement warrants quoting, a separate narrow call reads exactly two notes (~18k characters, safe by construction) and returns the quoted grounds. Gather itself never reads full notes. This stage is built only if stage 9's output shows it is needed.

**Call-count effect.** v0 ran about 56,000 note-level calls (18.8k notes × 3 tag draws, plus 18.8k cross-reference calls). v1 runs roughly 6,000: a 9000-character cap yields about a third as many notes, and each is read once. Cost is measured by the probe in slice 02 (P0-6), not estimated here.

**Phase B is degraded until it is rewritten.** `axial brief` filters on the closed vocabularies this pipeline retires. Nothing here fixes it, and nothing here should: rewriting Phase B against name pages is its own feature (§3 non-goal 7).

## 7. Data & configuration contracts

### 7.1 Domain frame & loader contract

The domain frame is two files. `config/domains/syria/schema.yaml` declares the fields and the example lists (Appendix G). `config/domains/syria/codebook.yaml` adds, per example, a one-line definition and one positive + one negative example. In v0 these were a controlled vocabulary and a labelling instrument. In v1 they are **prompt context**: what a good answer to each question looks like in this domain, shown to the model *after* it has answered in its own words (D8, D9).

Loader contract:
- The loader reads the frame and exposes, per question that has one: the example list, and each example's definition and positive/negative example. It exposes no cardinality rule, because no answer is a slot to fill.
- **No value is validated against the frame.** There is no membership check, no bounded correction re-ask, and no quarantine for an off-list value. An answer that matches nothing in the frame is the expected case (§7.15's free-answer-first rule makes it the normal one), and it is recorded verbatim.
- **The nearest-example field is the model's own, and is marked.** Where a question carries examples, the record has a second, clearly separate field naming the nearest example and how well it fits (§7.15). Code never derives it, never normalizes a free answer into it, and never rewrites either.
- The frame carries a `version` field; every note records the frame version it was interrogated under, so a later frame change is detectable per note.
- `polity_canonical.yaml` is loaded by Reconcile only (§7.16), as a seed for the alias map. It is a cleanup aid. An unmapped name always passes through.
- Swapping domains = pointing the loader at a different `domains/<name>/` directory. No code path branches on country.

> **STRUCK (D9).** The off-list validator, the bounded correction re-ask, the `out_of_vocab` quarantine, and the `unlisted` / `not-applicable` sentinel machinery that existed to soften them are retired with the tagging pass (D4). Removing the code is slice 03's job; nothing in v1 calls it.

### 7.2 Note, artifact and name-page metadata

**Prose notes** carry three metadata levels plus their answers (example in Appendix H):
- **Source-level:** author, title, date, the author's stated thesis, and scope. Composed from two artifacts: `author`, `title` and `date` come from the source-metadata record (§7.12, §7.13); thesis and scope come from the envelope (§7.3).
- **Section-level:** the author's own section/chapter labels, kept verbatim as the source's self-description.
- **Note-level:** the **interrogation answer record** for that note (§7.15), written into frontmatter as-is, plus the frame version it was interrogated under.

The note carries **no links** (D11). Its `names` answers are plain strings, not `[[wikilinks]]`; the link layer lives one node away, in the name pages, so re-reconciling names never rewrites a note. A note is written once and changes only if its source or the interrogation changes.

**Artifact notes** carry source/section provenance and the caption, when one is attached. They carry no `cited_by` back-references. **They carry no `artifact_role` (issue #429):** the artifacts pass makes no LLM call, and `retrievable` is a rule over caption presence, not a model judgment.

> **STRUCK (D5).** `cited_by` on artifact notes and `artifact_refs` on prose notes were the cross-reference pass's output. Both are retired with it. Their replacement is stronger: a figure or table is a nameable thing, the interrogation names it like any other entity (§7.15, `kind: figure` / `kind: table`), and it gets a name page whose members are every note that named it (§7.17). **Confirmed in slice 06 (issue #411):** a `figure`/`table`-kind name page also links the artifact-pool note for the same figure, resolved by a bounded, deterministic substring match — the canonical name or an alias appears in an artifact's caption, restricted to the source(s) the name's own member notes came from (never cross-source). Not a model judgment; `axial.materialize.find_artifact_links`.

**Name pages** carry the canonical name, its kind, its aliases, its member count, and its member notes as links; Gather adds the disagreement section (§7.17, §7.18).

### 7.3 Structural envelope

One JSON per source in `data/envelopes/`: `{source_id, thesis, toc[], scope, stated_argument}`. Produced once in stage 3. **In v1 it is consumed by Interrogate (stage 6), not by a tagging pass**, and its role is larger than it was: the thesis, scope and stated argument are threaded into every per-note call as the book-level context a model reading one paragraph cannot otherwise have (§7.15). It remains reusable by downstream phases outside this PRD. The shape is **locked**: `thesis`, `scope`, and `stated_argument` are non-empty strings; `toc` is a **non-empty list of `{title, children[]}` objects**, each object's `title` a non-empty string and its `children` a list of strings (possibly empty), so parts hold chapters and chapters hold sections; and no field is nullable.

Two amendments changed this locked shape, both deliberate. #235 **changed the `toc` element shape** — a flat list of strings became this nested list of objects — adding and removing no field; that change was founder-approved directly. The second **removes `author`, `title` and `date` from the envelope entirely** (§7.13): those are facts about the file, they are now read at intake, and they live in the source-metadata record (§7.12). This removal follows from the founder's decision to read the three fields at intake rather than being separately ruled on: keeping them in the envelope as well would recreate the two-sources-of-truth problem that decision exists to end. The pass was never able to fill them honestly — `author` and `date` are null in all 30 envelopes and `title` is the filename slug title-cased, which is a fabrication, not a reading. Removing them makes the no-field-is-nullable rule true rather than aspirational. Neither amendment ripples into note shape: the vault's `source_meta` block keeps its five keys, now composed from both artifacts (§7.13).

What the envelope is left holding is exactly what it is good at: what the model concludes about the *work* from reading its argument. Everything the file states about itself lives one artifact upstream.

**Evidence floor on the input.** The pass must never ask the model for a thesis over an empty or near-empty evidence block. Its input selection starts from the intro / abstract / conclusion heading heuristic. That heuristic matches nothing on a source whose top-level sections are titled by topic, and an empty evidence block is exactly what lets the model free-associate a plausible-but-wrong thesis (#201; the observed defect summarized Agamben's *State of Exception* as an internet-governance paper). So when the heuristic selects little or no text, the input **widens to a substantive head-of-tree slice**: a bounded prefix of the source's own prose, taken in tree order, large enough that the model always sees real source text before it is asked for a thesis. The slice proceeds in tree order but **skips a leading front-matter / apparatus prefix** — title page, copyright and ISBN block, publisher boilerplate, preface scaffolding — and begins counting at the first genuinely substantive body prose, so a source whose head-of-tree is a wall of front matter still yields real argument text (#222). It still reads in tree order; it just does not start the bounded count until real body prose begins. How much leading apparatus may be skipped before the count starts is a stated **tunable**, not a magic constant, bounded so the skip can never consume the whole source. The slice size is likewise a stated **tunable**, proven via inspection in the spirit of the chunk band (§7.7) and the low-alpha threshold (§7.8). The guarantee is an observable **minimum-evidence property**: the evidence assembled for the envelope call always carries **substantive argument prose** — never an empty or whitespace-only section block, and never a mis-sectioned bibliography that merely clears the character floor (below, #222) — for every source, including one whose top-level headings match none of intro / abstract / conclusion.

**Evidence is the full text of the selected sections.** The evidence for a matched section is that section's **own** prose together with its children's, not its children's alone. A flat intro whose text hangs directly on the matched node still yields real evidence; the matched node's direct text is never dropped.

**Bibliography-by-aggregate exclusion.** A matched intro / abstract / conclusion section is not always argument prose. docling sometimes **mis-attaches a source's bibliography under a body-section heading** — an "Introduction" or "Conclusion" heading whose descendants are in fact a reference list, fragmented into individual one-citation leaf nodes (#222; observed on the Tilly source, whose mis-sectioned reference wall runs to ~9k characters). That wall of citations clears the character-count evidence floor above, so without a further check the pass hands the model a bibliography instead of an argument and gets back a grounded-but-shallow thesis — the section heading echoed as prose. This is distinct from #201: the model does not confabulate, it correctly refuses to invent; it simply has no argument prose to work from. The envelope's matched-section selection therefore computes an **aggregate citation signal across the section's descendants** — the share of the section's leaf nodes that are single-citation / bibliographic entries (e.g. inverted author-name entries, "Lastname, F. …", and citation-list line structure, counted across children) — and when that aggregate share is high enough, treats the section as **non-prose apparatus and excludes it from the matched-section evidence before the evidence-floor check**. A bibliography-poisoned "Introduction" or "Conclusion" then no longer masks the floor, so the pass widens to the head-of-tree slice above and finds real body prose. The signal is deliberately an **aggregate across a section's descendants, not per-block density**: the §7.8 content-apparatus arm keys on citation density **within a single block**, and this bibliography's citations are fragmented one-per-leaf, each leaf below that per-block threshold, so the §7.8 arm flags zero of them (it still catches the same apparatus once chunked, because a chunk aggregates many citations into one dense block; the envelope reads pre-chunk tree leaves — a different granularity, which is why the envelope needs its own aggregate signal). The aggregate share that marks a section bibliographic is a stated **tunable**, proven via inspection. Mirroring §7.8's **never-drop-on-uncertainty** principle, the detector is **conservative**: it fires only on a high-confidence bibliographic aggregate, never on ordinary argument prose that merely cites sources in passing; when the signal is uncertain, the section stays prose. The **minimum-evidence property** is thereby strengthened: the assembled evidence must be substantive argument prose, so a bibliography that clears the raw character floor does **not** satisfy it.

**Grounded by construction.** The prompt instructs the model to base `thesis`, `scope`, and `stated_argument` **only on the supplied source text**, and explicitly **not** to infer from the title, the filename, or outside knowledge. No envelope field may be derived from anything but the provided text. The `title` is read at intake and recorded in the source-metadata record (§7.12, §7.13); it is not an envelope field and is never a source for the extracted fields. Reasoning is **ON** for this call (§7.9): the extraction is judgment-heavy, once per source, and its output is now context for every interrogation call downstream.

**Table of contents by two-signal reconstruction.** The `toc` is not thesis evidence and is not a flat dump of detected headings. The model **reconstructs** the source's real table of contents, within the **same single envelope call** (§5 keeps the envelope at one API call per source), grounded in exactly **two signals** read from the cached structural tree and nothing else — no title, no filename, no outside knowledge. **Signal A** is the source's opening pages, read as a front-matter-**inclusive** head-of-tree slice: it deliberately keeps the printed table-of-contents page when the source prints one, because that page is the best signal for a clean chapter list. This is a **distinct slice** from the front-matter-**skipped** evidence the thesis / scope / stated-argument extraction uses (the evidence-floor machinery above, #222 / #225): the printed TOC page is noise for the thesis but the source for `toc`, so it is kept out of the thesis evidence and fed only to the toc reconstruction, which resolves the dual role with no router change. **Signal B** is the flattened list of the tree's detected top-level headings; docling has flattened the heading hierarchy into one `section_header` level, mixing genuine chapter titles with subsection headings, OCR-garble fragments, and body sentences mislabelled as headings. From these two signals the model reconstructs the nested `{title, children[]}` hierarchy: it prefers the printed TOC in Signal A when present and legible, otherwise reconstructs from the genuine chapter / section headings in Signal B. It excludes subsection noise, OCR-garble, mislabelled body lines, and pure apparatus (index, bibliography, list of figures / tables) unless one is a genuine part. Grounding is **by construction**, the same guarantee "Grounded by construction" makes for the other fields: the prompt instructs the model to use ONLY the two supplied signals. If the reconstruction fails validation, the pass falls back deterministically to the tree's own detected heading list, preserving the non-empty guarantee (#235). The `toc` is also what supplies each note's **chapter** context to the interrogation (§7.15), so it now has a live consumer inside Phase A.

### 7.4 Structural tree

One JSON per source in `data/trees/`, keyed by `source_id` (the same deterministic id used for the envelope — `axial.envelope.compute_source_id`): the hierarchical tree from stage 2 — a root with `children`, each node carrying a `type` (`prose` or `artifact`), an `order`, and the docling structural **`label`** (the block type — e.g. `text`, `section_header`, `title`, `list_item`, `table`, `caption`, `footnote`, `document_index`, `picture`) preserved verbatim from extraction. The `label` is what the source router (§7.8) classifies on; it is a finer-grained signal than the two-value `type`. The shape is exactly the extraction pass's output (whether from docling or the Unstructured fallback); the tree's structure and every block's `label`, `type`, and `order` are preserved from extraction. This subsection adds persistence and a text-normalization pass (below) — not a new shape. Produced once in stage 2 and reused by every later stage for that source (the chunk, artifact, interrogate and materialize passes all read the persisted tree or its derivatives). A source is re-extracted only when no persisted tree exists for its `source_id`. **This is what makes D16's re-run cheap:** every stage below extraction re-runs over the whole corpus, and none of it re-processes a book.

**Post-extract text normalization.** The docling PDF text-layer *decoding* garbles glyphs a clean source renders correctly (this is not OCR — extraction runs with `do_ocr=False`; the defect is in decoding, not scanning). Before the tree is persisted, a **deterministic, model-free normalization pass applied at tree-build time** repairs those defects in each block's `text`. Because it runs here, once, every downstream pass inherits clean text, and a re-extraction regenerates the normalized tree. Normalization touches **only `text` values**: it never changes the tree's shape or any block's `label`, `type`, or `order`, so the source router (§7.8) classifies exactly as before. It is organized as **independent transforms, each a no-op when its target defect is absent** — a clean-font source (correctly decoded to begin with) passes through materially unchanged.

- **Whitespace (universal).** Strip soft-hyphens (U+00AD); collapse runs of whitespace to a single space; remove space-before-punctuation. This defect is near-universal and zero-risk.
- **Glyph repair (font-specific, no-op when absent).** Drop or reattach detached combining marks (Unicode category Sk — e.g. a detached macron, acute, diaeresis, or cedilla left stranded by decoding); decode Private-Use-Area offset glyphs where the offset is recoverable (e.g. `chr(c − 0xF700)`) and drop them where it is not; map a **curated allowlist** of known glyph-name leaks (`asper`→ayn `ʿ`, `lenis`→hamza `ʾ`, and `H####`/`Q##` font-internal codes → drop); normalize dotless-i. Each font-specific defect is isolated to one or two sources with disjoint glyph sets, so each transform stays a no-op on sources that lack it.
- **Small-caps letter-spacing repair (out of scope).** Small-caps rendering appears to insert spurious inter-letter spacing (e.g. `"I saw"`→`"Isaw"`), and this was projected as the one universal defect. Measured on the normalized trees, that projection was an artifact of pre-normalization double-spacing: after the whitespace transform runs, the residual is near-absent — zero in most books, and what remains is one book's front-matter cosmetics plus corrupted OCR-garbage tables. The dominant match in real prose is a legitimate article plus acronym (e.g. `a U.S. …`) that a merge would corrupt. No safe spacing-only repair exists, because a two-word small-caps run has identical spacing between its letters and between its words, so a length-gated merge concatenates across the word boundary. It is therefore **out of scope** for the normalization pass.

**Safety principle — curated allowlist, never a pattern strip.** Glyph-name repair matches only the specific leaked names on its allowlist; it must **never** strip slash-words as a class. Real prose contains legitimate slash-words in every corpus source — `and/or`, paired terms like `threat/opportunity`, URLs like `/reliefweb`, page-references like `/p111` — and a blanket `/word` strip would corrupt them. When a leaked name is not on the allowlist, the pass leaves the text unchanged rather than guessing.

**Explicitly out of scope (untouched).** Middle-dots (`·`, a legitimate notation), correctly-composed accents, and mathematical symbols are **not** normalization targets; the pass must not alter them.

### 7.7 On-disk note artifact (chunks)

The chunk stage (§5 stage 4) writes its prose chunks to disk as a cheap, inspectable artifact **before any LLM is called on them** — one JSONL file per source in `data/chunks/`, named `<source_id>.jsonl` and keyed by the same deterministic `source_id` used for the tree and envelope (`axial.envelope.compute_source_id`). One JSON object per line, one line per chunk, in section-then-position order. **A chunk record is a note**: the interrogation pass, the materializer, and every later stage read `data/chunks/<source_id>.jsonl` directly. The mandated invariant is that boundaries are computed **once** by the chunk stage and **never re-derived** downstream.

Each chunk record carries at least:
- `chunk_id` — a stable, deterministic id of the form `<source_id>_<section order>_<section slug>_<NNN>`: no randomness, no timestamps, identical across re-runs on the same source bytes. This is the established `chunk_id` scheme, preserved unchanged. The `section order` component keeps two distinct sections that share a heading from colliding.
- `section` — the section's own verbatim heading text (section-level provenance).
- `section_order` — the section node's `order` from the persisted structural tree (§7.4), which disambiguates repeated headings and lets a resume tell which sections are already persisted.
- `text` — the note's prose, bounded into the two-sided size band `[CHUNK_MIN, CHUNK_MAX]` = **`[3500, 9000]` characters (D1)**: **every record's `text` falls within the band** — no record exceeds `CHUNK_MAX`, and, save for the sole-chunk case below, no record falls below `CHUNK_MIN`. Note size is measurable directly off this artifact, so the band is a testable property.

Additional fields may be added (e.g. a character count) but the four above are the invariant contract.

**The band, and the two invariants that follow from it.**

- **`[3500, 9000]` (D1).** The old band was `[1000, 3000]`, anchored on what the vault stored. The new band is anchored on the unit §7.15's questions are answerable over: a claim and its evidence usually sit several paragraphs apart, so a 3000-character window holds half an argumentative move. Both constants live in `src/axial/chunk.py` as `CHUNK_MIN` / `CHUNK_MAX`; changing the band is changing them, and nothing else in the mechanism moves.
- **No note spans two chapters (D2).** This is already guaranteed by construction and is recorded here as an invariant so it is not re-litigated: chunks are built inside a single section node, so a chunk can never cross a heading. Merging is same-section only. No work is required to hold this, and any future change to the merge rule must keep it.
- **A short section yields one short note, and that is accepted (D3).** The below-floor merge is same-section only, and a section that is its own sole group is kept as-is. A section whose total prose is under `CHUNK_MIN` therefore produces one below-floor note. That is the price of D2 and it is deliberately paid: the alternative is merging across a heading, which would put two chapters' prose in one interrogation. The count of such notes is reported by `axial chunk examine`, so the trade-off is visible rather than assumed.

**Re-cutting the notes re-runs everything below extraction (D16).** `chunk_id` folds the section order and a per-section index, so a band change renumbers every note in the corpus. Every artifact keyed by `chunk_id` — answer records, vault notes, the name inventory, the alias map — stops matching and is rebuilt. That is a designed consequence, not a migration: most of what breaks is being deleted anyway (tags, cross-reference pairs, the gold set, the corpus pin). The structural trees are cached (§7.4), so no book is re-extracted and the re-cut is hours, not days. **Figure and table records come off the cached structural tree, not off the notes, so their descriptions should not need re-paying — confirmed in slice 01, never assumed.**

A block dropped upstream by the source router (apparatus — label-driven or content-detected, §7.8), a section skipped by the residual garble backstop, or an emitted candidate removed by the post-split fragment floor (§7.8, #193) contributes no chunk records; every such drop and its reason are recorded to the **router-owned skip record** — the single source of skip truth (§7.8) — so a reader can always distinguish a deliberate drop from a silent loss. Size never triggers a skip: a large but legitimate section is split into multiple in-band records, and a below-`CHUNK_MIN` chunk is merged into a same-section neighbour (§7.8 / P0-4), never dropped. An edited source (which yields a new content-hashed `source_id`) never reuses another source's stale artifact.

**Inspection (examine).** `axial chunk examine` reads the on-disk chunk artifact and reports note-quality stats with **zero LLM and zero embedding-model calls**: total and per-source counts; the size distribution (min / max / mean / median), from which the two-sided band is verifiable before any LLM spend; a boundary-sanity summary — the count of notes above `CHUNK_MAX` and the count below `CHUNK_MIN` (both expected to be zero under the band, modulo the sole-chunk exception of D3), the count of sections split into multiple notes, the count of sub-floor chunks merged into a same-section neighbour — and the count of blocks the router dropped with their reasons, read from the router-owned skip record (§7.8); and an eyeball sample of texts showing where boundaries fall. It runs entirely off the JSONL artifact, calls no inference or embedding model, and never mutates the artifact.

### 7.8 Routing decisions (source router)

At step 2b (§5), between structural extraction and the passes that consume the tree, a single **source router** classifies every tree block by its docling structural `label` (§7.4) into exactly one of three **routes**, and every downstream pass consumes that one classification rather than re-deriving a prose/non-prose decision. The router reads the persisted tree only and triggers no re-extraction. It calls **no model for the `label`→route mapping**; its one exception is a bounded per-block classification of content-flagged apparatus candidates (**Content-detected apparatus** and **Model-backed classification of flagged candidates**, below), which the overwhelming majority of blocks — all clean prose — never reach.

**Routes and the `label` → route mapping:**
- **prose** — `text`, `section_header`, `title`, and an in-body `list_item`. Routed to the chunk stage (§5 stage 4, §7.7). These are the only blocks that ever reach the chunk path.
- **artifact** — `table`, `picture`, `caption`. Routed to the artifact classification pass (§5 stage 5 / P0-5), which is their sole home; a `caption` attaches to its figure or table. Artifact blocks never enter the prose chunk path.
- **apparatus** — `document_index` (TOC / index), `footnote` (endnotes / footnotes), `page_header`, `page_footer`, and a `list_item` whose enclosing section is back-matter. **Dropped:** not chunked, not artifact-noted. Each drop is recorded with a reason.

**Founder decisions (charter #164):**
- Endnotes and footnotes are **dropped as apparatus** — not chunked and not sent to the artifact pass.
- Tables and charts **keep the artifact classification pass** — they route to the artifact pass (which adds id/source/section provenance and attaches a caption), not raw docling → vault. The pass adds the provenance the raw block lacks, so bypassing it would lose information. It no longer adds a role (issue #429: the pass makes no LLM call).

**`list_item` under back-matter.** A `list_item` is **prose by default**, so in-body lists are chunked; it is apparatus **only** when its enclosing section is back-matter (e.g. a bibliography or reference list rendered as list items). `document_index` already catches most TOC / index blocks; this rule covers the residual reference-list case.

**Unknown label fails open to prose.** A block whose `label` is absent, empty, or not in the mapping is routed to **prose**, never silently dropped. A misclassified block then surfaces as visible prose to be caught and corrected, rather than vanishing — the router never drops on uncertainty.

**Single source of skip truth.** Apparatus drops — both **label-driven** (the `label`→route mapping) and **content-detected** (the content arm below) — are recorded to the **router-owned skip record**, which carries label-driven apparatus drops, content-apparatus drops, and any genuine-garble backstop skips, each with its own reason. This record is the one place a reader distinguishes a deliberate drop from a silent loss, and it is what `axial chunk examine` reads for its dropped-block report (P0-4b). The per-pass size/garble guard (`non_prose_skip_reason` — a `>30k chars` / `>40% non-alpha` heuristic formerly re-decided independently at each LLM entry) is **demoted to a backstop** for genuinely garbled prose that slips type classification, applying its non-alpha arm only (`garble_only_skip_reason`) at the chunk and interrogate passes; it is no longer the primary prose/non-prose gate there and cannot see block *type*, which is why a clean TOC or a well-formed endnotes section sailed through it before routing existed. (`non_prose_skip_reason` no longer has a caller at all: the artifact pass was its last live user, and issue #429 dropped the guard there along with the LLM call it protected — an artifact record carries no node text to protect from a garbled OCR read, and the guard's own size/garble decision has no bearing on whether an attached caption is worth keeping.) Whatever a pass still skips at its own call site is **recorded durably**, not just logged to stderr: the sidecar-less form of this guard measurably lost 34 legitimate chunks with no trace across the 2026-07 corpus rerun, which is the defect the skip record exists to prevent.

> **STRUCK (D4).** The tag pass's retuned `60%` non-alpha threshold is retired with the tag pass. It was measured at that one call site, over the v0 corpus, at the old note band; with the pass deleted and the band changed (D1) it is not carried forward by assertion. The interrogation pass applies the shared `MAX_NON_ALPHA_RATIO` default, and any retune for it is measured on the re-cut corpus before it is set, exactly as the original was.

**Post-split fragment floor (#193, generalized in #197).** The garble backstop above runs at the *section* level, on the joined body before the recursive splitter runs, so it cannot see a junk *tail chunk* a legitimate prose section leaves behind after splitting. A narrow floor closes that gap. After the chunk stage splits a section and applies the band guard (§5 stage 4), it drops an emitted candidate chunk — before the chunk is written to the artifact (§7.7) — when, and only when, the chunk is unambiguous non-content boilerplate of one of two shapes: (a) a **blank-page notice** — its text equals `this page intentionally left blank` after lowercasing and whitespace collapse; or (b) a **low-alpha fragment** — its **alphabetic ratio**, the count of alphabetic characters divided by the total character count, is below **the low-alpha threshold, currently 0.45**. The threshold is a tunable starting value proven via `axial chunk examine`, framed like the size band's `min`/`max`, not a magic number. This shape generalizes #193's zero-alphabetic-content rule, which is the ratio-0 special case: a fragment with only digits, punctuation, whitespace, or symbols (e.g. `6`, `200…`, `13).`) has ratio 0 and still drops, and citation and significance-star crumbs such as `∗ p < 0.` (ratio 0.12) or `Berman 1996: 78 ).` (ratio 0.33) now drop too. A blank-page notice is alpha-heavy — a high ratio — so shape (a) catches it, never shape (b). Each such drop is recorded to the router-owned skip record with its own distinct low-alpha-ratio reason, so it is a visible deliberate drop, never a silent loss. The floor acts **post-split, on individual emitted chunks**, not at the section level: the leaking crumbs are section *tails* whose parent section is legitimate prose, so a section-level filter never sees them.

**Genuine short prose is protected (#193).** This is a first-class invariant, not a side effect, and it stays primary. A chunk whose **alphabetic ratio is at or above the low-alpha threshold (≥ 0.45) is always kept**, however short — a real sentence such as `Yet, the U.S.` (ratio 0.62) or the interview quote `The Germans did not come to hurt us' (I25).` (ratio 0.66) survives. **Length alone never triggers a drop**, mirroring the "size never triggers a skip" principle (§7.7); only a low alphabetic ratio, or the blank-page shape, does. "Protected" means the chunk's **text** is never dropped — not that it survives as a **standalone chunk record**: a short sub-`CHUNK_MIN` chunk with a same-section predecessor is **merged backward** into it (P0-4, respecting `CHUNK_MAX`), which preserves 100% of its text. The MIN-side exception keeps a sub-floor chunk standalone **only** in the sole-chunk case (§7.7 D3, P0-4). This protection is the opposite of the fragment floor, which **drops** unambiguous junk regardless of merge. The threshold sits in a clean gap in the measured corpus: junk crumbs sit at ratio ≤ 0.33 and genuine short prose starts at ≥ 0.60, so 0.45 is mid-gap with roughly a 0.12 margin on either side. What stays out of scope is the **0.53–0.60 mid-band**: multi-citation crumbs interleaved with genuine quoted testimony that cannot be separated mechanically without false-dropping real content — the #193 trap — so the floor deliberately does not reach into it.

**Content-detected apparatus (the residual reference-list case).** The `label`→route mapping catches apparatus that docling *labels* as apparatus. It misses apparatus docling labels as plain **prose**: a reference list, bibliography, or endnote run mis-sectioned under a body heading (e.g. "Chapter Two", "Introduction") and emitted as `text`, so the `document_index` and back-matter `list_item` rules never see it. Heading and title matching cannot catch these — the heading lies — so only the block's *content* reveals it. The router therefore adds a **content arm**: a block the `label` mapping routed to prose is re-examined, and when it is **detectably reference / citation apparatus by content** — a dense run of bibliographic citations, e.g. inverted author-name entries ("Lastname, F. …") recurring past a threshold, and/or citation-list line structure — it is re-routed to **apparatus** and dropped like any other apparatus block, its reason recorded in the router-owned skip record with a distinct content-apparatus reason. The content arm is deliberately **conservative**: it fires only on high-confidence citation density, never on ordinary prose that merely cites a source or two in passing. It does not override the **unknown-label / never-drop-on-uncertainty** principle above: a block the content arm does not confidently identify as apparatus stays prose, so the router still never drops on doubt. Every content-apparatus drop is recorded with its reason and is inspectable via `axial chunk examine` (§7.7, P0-4b) without LLM spend. This arm is **per-block**: it keys on citation density within a single block. A bibliography fragmented into one-citation-per-leaf nodes clears no single block's density threshold, so a separate **aggregate-across-descendants** signal is needed to catch it in the envelope's pre-chunk evidence selection (§7.3, #222); this per-block arm still catches the same apparatus downstream, once chunking aggregates its citations into one dense block.

**Model-backed classification of flagged candidates.** The content arm is two-stage so that clean prose never incurs model spend. First, a **cheap, deterministic pre-filter** — the citation-density signal above — flags candidate blocks; a block the pre-filter does not flag is never sent to a model and routes exactly as its `label` dictates. Second, **only the flagged candidates** are sent to a single, bounded classification call that returns one decision per block against the existing **prose / artifact / apparatus** taxonomy, resolving each flagged block to **apparatus** (drop, recorded in the skip record with its reason) or **prose** (kept; reaches the chunk stage). This is the **only** point at which the router calls a model, and it is an explicit, bounded, per-block classification — not a free re-derivation of the tree. Because the pre-filter gates it, clean prose reaches the chunk stage with **zero** model spend. Reasoning is **ON** for this classification call (§7.9): the drop-or-keep decision is judgment-heavy and low-volume. **A failed classification call fails open, never closed.** If the bounded call itself fails (a transport error, or an exhausted re-ask budget on unparseable JSON) rather than merely returning an ambiguous verdict, the flagged block is kept as prose — the same never-drop-on-uncertainty rule extended from a bad *answer* to a failed *call* — and chunking continues for the rest of the source; the failure is logged, not raised.

**One shared classification.** The route is computed once and shared by every consumer (chunk, artifact, interrogate); no downstream pass re-derives the prose/non-prose decision. Whether the route is **persisted as an annotation on the tree** (§7.4) or **recomputed on read** from each block's `label` is an implementation choice — the contract **sanctions either**; what it mandates is that all consumers share the one classification.

### 7.9 Per-pass model routing and reasoning

The **model** a pass calls, whether **reasoning** (an extended chain-of-thought token budget) is on for it, and its **sampling temperature** are all **per-pass** settings carried in `config/pipeline.yaml` (`model_by_pass`, `reasoning_by_pass`, `temperature_by_pass`), never hardcoded at a call site. A pass identifies itself by a pass-name constant in `src/axial/llm.py`; an unnamed pass silently resolves to every safe default, which is why naming a new pass is part of building it. The three blocks share one shape and one resolution: config overrides a code-level default, and a pass absent from a block keeps the behaviour it had before that block existed. For temperature that default is **to send no `temperature` field at all**, leaving the model's own default — so a pass gains a temperature only by being named.

Reasoning was disabled globally after #147, when the `production_low` model pressed into service as a reasoner blew the wall-clock on the large per-chunk calls; that fix over-generalized. The rule that replaces it: **reasoning is ON where the decision is judgment-heavy and the call count is low, OFF where volume dominates.**

| Pass | Pass name | Volume | Reasoning | Model |
|---|---|---|---|---|
| Structural envelope (§5 stage 3 / P0-3) | `envelope` | 1 per source | **ON** | `production_high` tier (DEC-26) |
| Holdings-completeness check (§7.11 / P0-1b) | `holdings` | 1 per source | **ON** | tier per config |
| Content-apparatus classification (§7.8) | `content_apparatus` | flagged blocks only | **ON** | tier per config |
| **Note interrogation (§7.15 / P0-6)** | **`note_interrogate`** | **~6,000, 1 per note** | **OFF by default** | **`z-ai/glm-5.2` (D14)** |
| **Reconcile merge (§7.16 / P0-12)** | **`reconcile`** | per cluster, low | **ON, effort `high`** | tier per config |
| **Gather (§7.18 / P0-13)** | **`gather`** | 1 per name, plus a merge call per batched name | **ON** | tier per config |
| **Pairwise support (§7.18 / P1-5)** | **`pairwise`** | on demand | **ON** | tier per config |
| **Gather grounding eval (§10, DEC-54)** | **`gather_eval`** | 1 per scoreable disagreement entry | **ON, effort `high`** | `production_high` |

Notes on the four new entries:

- **`note_interrogate` runs on `z-ai/glm-5.2` (D14),** through a **tier of its own**, `production_interrogate`. It is not routed to `production_high` (the envelope pass's tier, `deepseek/deepseek-v4-pro`) and not to `production_synthesis` (Phase B's, which happens to name the same model today): pointing it at either would mean a later swap of one silently moves the other. That family was high-variance on the book-level envelope pass and was reverted once for exactly that (DEC-27 / DEC-28), so this routing is not taken on trust. The run **samples ~50 outputs at the start and stops** (P0-6): the operator reads them before the remaining ~5,950 calls are paid for. A model that reads badly is caught for the price of 50 calls, not 6,000.
- **A tier no operator's secrets file names fails that pass alone.** `config/pipeline.yaml` is shared and `secrets/secrets.toml` is not in the repo, so a new tiered pass would otherwise break every other pass on every checkout that has not added the key yet. Resolution therefore defers: an unresolvable tier is recorded and raised, with the same message and the same loudness, when the pass that names it is called. It is **never** softened into a silent fallback to a cheaper model — that is the failure DEC-26's guard exists to prevent.
- **`note_interrogate` reasoning is OFF by default**, matching every other high-volume per-note pass (#147). The 50-output sample gate is where that default is tested: if the sample shows the answers need it, turning reasoning on is a config change, and the sample is re-read before the corpus run proceeds. It is not turned on by assumption.
- **`note_interrogate` must not reuse the pass name `"interrogate"`.** `INTERROGATE_PASS_NAME = "interrogate"` (`src/axial/llm.py:303`) already belongs to Phase B's brief-interrogation pre-pass (`src/axial/brief/interrogate.py`). Sharing the name would silently share this pass's model and reasoning settings with a Phase-B pass that wants neither.
- **`gather_eval` is pinned to `production_high`, deliberately different from `gather`'s own (unpinned) tier.** The pass that judges a disagreement grounded must never be the pass that wrote it (§10, `CHARTER.md` §2) — the same self-grading guard `attribution`/`counter_position`/`grounding`/`calibration` already carry.
- **Model tier for `gather` and `pairwise` is left to config and is not fixed here.** No measurement exists for them yet, and asserting a tier without one is how DEC-27 happened. **`reconcile` now has one**: a 30-cluster probe over the real corpus (2026-07-28) put `production_low` at one clear error and one questionable canonical in 30 decisions, including the sample's hardest call — given `Aldous Huxley` / `Huxley` / `Thomas Huxley` it kept the two people apart and folded only the ambiguous bare surname. It is named in `model_by_pass` so the pass cannot silently move when the global tier does. Cost did not decide it: a full pass is ~$0.55 there and a few dollars on any tier above, so this is a quality finding, not a budget one.
- **`reconcile` samples at temperature 1 with reasoning at `high`, and it is the only pass that names a temperature.** Deciding whether two surface forms name the same thing is an underdetermined judgment, and the project's own measurement says that shape of task is won by sampling and by letting the model think, not by prompt engineering (`docs/tag-reliability-best-of-n.md` §2.11, lesson 4). The consequence is deliberate: the prompt states the judgment and stops — no rule list, no criteria, no worked examples, and no instruction to think step by step, since reasoning at `high` *is* that mechanism. Reproducibility does not come from the sampler; it comes from Reconcile persisting each decision (§7.16).

> **STRUCK (D4, D5).** The `tag` and `xref` pass entries are retired with their passes, along with `votes_by_pass` and everything that read it (§7.14). The pass-name constants `TAG_PASS_NAME` and `XREF_PASS_NAME` are deleted by slice 03, not here.

### 7.10 Google Drive source contract

Sources are supplied by a Google Drive connector that streams the shared "Books" folder into the intake→extract pipeline. The connector is a first-class source provider: it enumerates the folder and pulls each file's bytes on demand, feeding the current intake→extract path (§5 stage 1, P0-11), with no operator-managed local staging step. Bytes may transit a temp/cache directory because docling needs a file path, but that cache is an implementation detail, not a staging contract.

**`[drive]` secrets.** Auth is a Google service account. `secrets/secrets.toml` carries a `[drive]` section, mirroring the existing `[openrouter]` pattern (§12, `secrets/secrets.example.toml`), with at least two keys: `service_account_json`, the filesystem path to the service-account JSON key file; and `books_folder_id`, the Drive folder id of the shared Books folder. The Books folder is shared with the service account's email out of band, so no interactive OAuth flow runs at connector time. Missing or incomplete `[drive]` secrets — an absent section, an absent or unreadable key path, or an absent folder id — raise a clear logged error and halt the connector before any network call. This is never a silent skip and never a partial run, mirroring the P0-1 intake reject discipline (§5 stage 1).

**File records returned by list.** The list operation returns a page of file records plus a `next_page_token`, and the connector paginates until the token is exhausted, so the enumeration covers the whole folder (P0-11). Each record carries at least: `id`, the Drive file id, which is the fetch-state key below; `name`, the filename, used for the `.pdf`/`.docx` filter and for provenance; `mimeType` or an equivalent format signal; and the change tokens `modifiedTime` and `md5Checksum`. The connector filters to `.pdf`/`.docx` candidates by name and mime type; final format and text-layer validation stays with P0-1 intake. The filter only narrows what is fetched, it does not replace intake's reject: a file that slips the name filter is still rejected at intake with a logged reason, so size or format never triggers a silent skip (§7.8, P0-1).

**Fetch-state manifest.** A persisted manifest records what has been fetched and ingested, keyed by Drive file `id`. Its location is `data/drive/fetch_state.json`, one manifest per run. Its shape is `id` → `{modifiedTime, md5Checksum, fetched_at}`: a change token per file. On re-run, a file present in the manifest whose listed `modifiedTime` and `md5Checksum` both match the manifest is skipped before download — its bytes are not pulled and it is not re-ingested. A file absent from the manifest, or whose change token differs from the manifest, is fetched. This pre-download skip composes with, and does not replace, the ingest-level `vault_status=OK` skip (P0-11b): the manifest saves the download plus the intake and extract work, the vault-status skip saves the downstream LLM work. The manifest is updated only after a file is successfully fetched and ingested, so an interrupted run re-fetches on the next pass rather than recording a false success. Observable: a second run over an unchanged folder fetches zero bytes and produces zero new sources.

**Language-gate tunables.** The English-only gate (P0-11c) detects language deterministically from a bounded text probe of the source, using a fixed-seed or otherwise deterministic detector (a `langdetect`- or `lingua`-style library, §12). It runs on every downloaded candidate, after download and before the source is handed to the ingest pipeline; intake's text-layer check (P0-1) runs later, inside that ingest handoff's extract stage, not before the gate. A probe that yields no detectable text — because the source is unparseable or carries no text layer — produces no language signal, and a no-signal probe is not a confident non-English verdict, so the gate does not reject it: such a source is passed through to the ingest handoff. The "never a silent pass-through" guarantee for a genuinely textless source is then held by the default ingest chain's intake check (P0-1), which rejects it with a logged reason before any docling conversion; a caller that injects its own ingest handoff owns that source's validation. Two tunables are stated here, not hardcoded magic constants, and are proven via inspection in the spirit of the chunk band (§7.7) and the low-alpha threshold (§7.8): `language_probe_chars`, the size of the leading text probe drawn from the source in reading order, bounded large enough to detect reliably and small enough to stay cheap; and `language_accept_threshold`, the minimum detector confidence for the dominant detected language to be accepted as English. A source whose probe detects English at or above the threshold passes to the ingest handoff; a source whose probe is confidently detected as a non-English language, at or above the threshold for that language, is rejected before extraction and logged with a reason that names the detected language and confidence. A confidently non-English source is never silently passed (§5 stage 1, mirroring the P0-1 reject discipline).

**Injectable client (offline testability).** The Google Drive API sits behind a small injectable client protocol, roughly `list_files(folder_id, page_token) -> (records, next_page_token)` and `download(file_id) -> bytes`. The real implementation wraps the Google client library; the connector depends only on the protocol, so a test injects a fake that returns fixture records and fixture bytes, and no test touches the network.

**Everyday entrypoint (`axial sources`, issue #528).** The operator picks a backend once, in `config/pipeline.yaml`'s `sources.backend` (`local` or `drive`); `axial sources` then reports what is new, changed, already done, partial, or rejected — with a reason for a rejection or a partial — and ingests whatever is new or changed, in that one shared vocabulary regardless of backend. The Drive backend is this section's connector unchanged: same fetch-state manifest, same language gate, same per-candidate isolation; `axial sources` and the pre-existing `axial drive ingest` both drive it. The local-folder backend answers the same question for `data/sources/` without a second manifest, and the artifacts on disk are the source of truth for it, not the ledger: a source with its envelope, chunks, structural tree, and interrogation answers all present is `done` whatever the corpus runner's own resume ledger (`data/run/ledger.tsv`) says or fails to say — the ledger's OK row is consulted first, purely as a fast path when it is present and agrees, never as the sole signal. (Measured live against the real 31-source corpus: the ledger-only design that shipped first reported all 31 `new`, because the unified ledger had never been written there and an older, differently-keyed one existed instead — an obviously wrong answer a rule must lose to.) A source with some but not all of its four artifacts is `partial`, naming exactly which are missing, since that is what tells the operator a run died halfway; `changed`/`new` are decided from the ledger's own path history only once the artifacts show none of the four exist. `axial sources --check` prints the same report and stops — no ingest, no pipeline or model call, no write — asking the question without committing to the (potentially expensive) action of re-ingesting the corpus. The two backends are not equally cheap to check: the local backend's report is free (a handful of `Path.exists()` calls and a ledger read, never a parse); the Drive backend's is not, since knowing whether a new or changed candidate would fail the language gate needs its bytes in hand, so a Drive check still downloads — it just never hands that download to ingest or writes the fetch-state manifest.

### 7.11 Holdings-completeness check

A **partial holding** is a source file that carries only part of the work it names: one volume of a multi-volume set, a truncated scan, an extract circulated as if it were the whole book. Two such sources sat in the 30-source corpus until #267 re-sourced both complete (see *Where the two true positives now live*, below). Nothing downstream detects them. The structural tree, the envelope, and the chunk artifact all describe the bytes that are present, faithfully, and say nothing about the bytes that are absent, so every later stage reports a partial holding as a healthy one. The check therefore belongs at intake (§5 stage 1), before extraction, and it reads the one artifact that still remembers the whole work: the source's own raw text layer.

The check reads **neither the structural tree nor the envelope**. That is load-bearing rather than incidental (see *Why not the tree*, below). It reads the raw text layer intake already builds for its text-layer check (P0-1), so the text costs nothing extra to obtain.

**The judgment is the model's.** An earlier design made the whole check deterministic — a printed-contents-page page-extent ratio, with a page-count-and-back-matter fallback for sources where no contents page was found. It was built, and it was measured, and it did not work. Recording why, so it is not rebuilt:

- **The document-kind distinction it could not make.** A research paper normally has no contents page at all. Neither does a chapter offprint. A rule keyed on the absence of a contents page cannot tell a complete paper from a truncated book, and the fallback arm therefore fired on `state-legitimacy`, a complete work: 2 true positives, **1 false positive**. Telling a paper from a book is a reading judgment, not a threshold.
- **The deterministic contents-page reader did not read contents pages.** Its entry matcher required dot leaders, which do not survive `pypdf` text extraction. It located **4 of 30** contents pages. Seventeen of the sources the design expected it to cover fell through to the fallback arm instead, and **26 of 30** sources in total were adjudicated by the arm the design had cast as the rare exception — the design inverted, the preferred signal becoming the scarce one. Those sources escaped false alarms only because their page counts exceeded the fallback's page ceiling, not because the fallback judged them. Three review rounds lifted the reader to **24 of 30**, with different membership than this document's earlier "21 of 30" figure — that figure is **corrected, not merely tightened**.
- **Tuning it toward the remaining cases makes it worse.** Widening the contents-region span far enough to reach `batatu`'s genuine five-page contents runs into its list of tables, where a line ending `…in Selected Years between 1963` parses as a page reference of 1963, collapsing the coverage ratio to 0.219 and firing falsely on a complete work. The obvious retune of a stated tunable produces exactly the failure the acceptance bar forbids.
- **Page furniture defeats literal matching.** `tilly`'s contents heading extracts as `viii Contents` — a running-header folio stitched onto the heading — which matches no literal `contents` rule. It scored clean only because the page ceiling protected it.

**Deterministic pre-processing, then one model call.** What is exact and cheap stays deterministic; what is a reading judgment goes to the model.

Deterministic, before the model sees anything:
- **Physical page count**, read from the file. This is the only reliable measure of how far the file actually runs.
- **Running header and footer stripping.** Lines that recur at the top or bottom of pages across the document — folios, running heads, running titles — are removed from the text before any of it is read for judgment. This is a **requirement, not an implementation detail**: it is what turns `viii Contents` back into `Contents`. A folio stitched to a heading must not survive into the text the model reads.

The model then makes **one judgment in one pass** over the cleaned front matter, plus whatever tail material the judgment needs. It is one judgment, not a set of independent signals scored separately, and it answers three things together:
- **What kind of document this is** — a book, a research paper, a chapter offprint, or a fragment.
- **What extent the document claims for itself**, where it states one: a printed contents page's last entry, a title page naming a volume of a set, a stated page range.
- **Whether the file covers that claimed extent**, given the physical page count.

**A research paper with no contents page is a normal, complete document and must not be flagged.** That distinction is the reason this check is model-adjudicated rather than deterministic; a paper is not a truncated book, and no threshold over page counts and back-matter density separates the two reliably.

**What the check produces.** A flag names what was concluded and carries the evidence for it, so an operator judges the finding rather than reading a bare boolean. The flag carries at least: the source it concerns; the **document kind** concluded; the **claimed extent**, where the document states one, with what stated it; the **observed extent** — the physical page count; and the **model's stated reason** for concluding the holding is partial. It **records its measurement**; it is never a bare boolean. A source judged complete produces no flag.

**Where it runs, and how often.** In the pipeline's own intake (§5 stage 1), which every ingest path funnels through — so it runs on every accepted source, not only when a caller asks for the judgment directly. It is a reasoning-ON model call, and intake re-validates a source on every later pass over the corpus, so the judgment is made **once per source** and persisted in the source-metadata record (§7.12); every later pass reads the record and calls nothing. The record is therefore what makes running the check unconditionally affordable. A source whose check could not run at all — no model available — is recorded as **unjudged**, never as complete, and is judged on the next pass: a `null` flag alone cannot carry that difference, so the record states whether the judgment has been made (§7.12).

**What the check never does.** It **flags and reports only**. It never rejects a source, never halts intake, never repairs or re-fetches, and never alters what any later stage sees. A flagged source proceeds through extraction, envelope, chunking, interrogation, and vault write exactly as an unflagged one does. This is deliberately unlike the P0-1 reject discipline: a missing text layer makes a source unusable, whereas a partial holding is usable and merely incomplete, and the call on what to do about it is the operator's.

**DOCX.** A DOCX file exposes no physical page count, so coverage against a claimed extent is not computable for it. The model can still read its front matter and tell a paper from a truncated book, so the check runs: it may flag a DOCX whose own front matter names it a part of a larger work (a volume, a stated page range the text plainly does not reach). It must not flag a DOCX for the absence of coverage evidence, since the evidence is unobtainable rather than damning. The earlier blanket DOCX exemption — no reading, no flag — is retired.

**Why not the tree.** Four candidate signals were proposed originally; a measurement pass over all 30 sources killed the tree-derived ones. Recording why matters, so they are not proposed again:
- **Printed TOC versus extracted tree cannot fire, by construction.** The router sends `document_index` to apparatus and discards its text (§7.8), and 198 such nodes corpus-wide carry no text. The envelope's `toc` is therefore a model reconstruction that truncates in lockstep with the tree it is reconstructed from. Measured, the two known truncated sources scored 0% missing while healthy sources scored up to 92%: the signal is inverted, not merely weak.
- **"Ends mid-sentence"** fires on 21 of 30 sources standalone and misses one of the two known instances entirely.
- **"An introduction with no subsequent chapters"** produces garbage on noisy and OCR'd trees.

Reading the raw text layer rather than the tree also keeps the check immune to the flattened and noisy-tree cases where tree-derived signals fail worst (Tilly, roughly 165 headings). That immunity is exactly what the rejected TOC-versus-tree signal lacked.

**The failure mode to watch.** No claim is made that this check degrades in a safe direction. An earlier version of this section asserted one, and it was false: routing a source from a primary signal to a fallback that fires on *absence* means degraded reading can produce a false alarm, not merely a miss (#282). The model-adjudicated check has its own version of the same exposure — a model can be confidently wrong about a document it read badly. There is no structural guarantee against it. What holds the line is the flag carrying its reason, so a wrong conclusion is visible rather than silent, and the corpus-level bar below, which is measured rather than argued.

**The bar is the contract; the mechanism is not.** The check flags exactly the two known partial holdings and nothing else: **2 true positives, 0 false positives, 0 false negatives** (#267, #268). That bar is strict and it does not move. How the check reaches it — which prompt, which model, how much front matter and tail it reads — is free.

**Where the two true positives went, and what replaces them.** #267 re-sourced both partial holdings with complete copies (Mann vol. 2 at 824 pages, Üngör at 216), so `data/sources/` no longer holds either partial file. An earlier revision of this section said the true-positive half was measured against those same two files truncated back to their old extents. **That construction is retired (#321).** The defective files were removed on purpose; re-manufacturing the defect to measure against is not evidence about real corpus behaviour, and the raw bytes are gone in any case.

The bar therefore splits, and the two halves are gated differently:

- **The false-positive half is measured every time the check changes**, over the 30 real sources in `data/sources/`: 0 flags. This is the half that runs against real bytes, and it stays the per-change gate.
- **The true-positive half is measured when the check's judgment changes** — the questions it is asked, its rules, its model, its windows — and not when prompt wording moves around them. It was last measured at #284: both truncations flagged, repeat runs 8/8 and 6/6. A change that leaves the numbered questions, the rules, and the anti-false-positive guard intact does not re-open it.

**Known exposure, stated rather than hidden.** No live positive control exists. The tests that assert a flag is raised feed a recorded model response, so they pin the plumbing and not the judgment; they would pass against a prompt that had stopped reading. Until one exists, "0 flags over 30" cannot by itself be distinguished from a check that no longer flags anything, and the true-positive half rests on #284's measurement rather than on anything re-run since.

If the design needs a tunable at all it should be **at most a small number** of them, and they should be stated. Three are, with values set by measurement (#284), not asserted: the **front-matter window** (20 pages — the corpus's printed contents pages start by page 8 and span at most 5), the **tail window** (3 pages — enough to tell a work that ends from one that breaks off), and the **running-furniture recurrence floor** (a head/foot line must recur on 3 or more sampled pages before it is stripped as furniture, so a two-page contents heading survives). No numeric threshold appears in this section that has not been measured.

### 7.12 Persisted source-metadata record

One JSON file per source at **`data/source_meta/<source_id>.json`**, keyed by the same deterministic `source_id` used for the tree (§7.4), the envelope (§7.3), and the chunk artifact (§7.7) — `{filename stem}-{first 12 hex characters of the sha256 of the source bytes}` (`axial.envelope.compute_source_id`). Written at intake (§5 stage 1), before extraction.

**Why it exists: it survives envelope regeneration.** The envelope is LLM-produced, nondeterministic, and regenerated routinely — the toc reconstruction rewrite (#235), the bounded re-ask (#241), a model trial, and more to come. Anything written into an envelope is therefore not a durable fact about the file; the next regen may change it, and a regen is a normal operation, not an incident. Facts about the *file* need a home a regen does not touch. Before this record existed, intake returned a metadata stub that was never persisted, and the only source-level metadata downstream could read was the envelope's — which is why the holdings flag (§7.11) had nowhere to live and reached no reader.

**What it holds.** Facts about the artifact:
- the **physical page count**, where the format exposes one;
- the **holdings flag** from §7.11, in full — the concluded document kind, claimed extent, observed extent, and the model's stated reason — or an explicit "no flag" for a source judged complete;
- **whether that judgment has been made at all.** "No flag" and "never judged" are different facts and a `null` flag states both, so the record carries the distinction separately. It is what lets the check run on every ingest without paying for it twice (§7.11): the ingest path reads this field, judges an unjudged source once, and skips the call for the rest of the corpus's life. It also keeps a call that never landed — an unavailable model — from being cached forever as a judgment;
- the **file hash**, the full sha256 of the source bytes;
- the **bibliographic fields** read at intake: author, title, date, publisher (§7.13);
- the **identifier** (§7.13) found in the source's own front matter — `null` (nothing found), `{type: "isbn"|"doi", value: <normalized>}` (exactly one found), or `{type, value: null, abstained: true, candidates: [...]}` (more than one distinct identifier found — ambiguous) — kept for audit even when it did not resolve, was ambiguous, or its fetch was rejected by the identity guard.

The file hash is already embedded in `source_id`, and storing it in full anyway is **deliberate**: the record should be self-describing, so a reader gets the hash by reading a field rather than by parsing the key and then discovering the key carries only a 12-character prefix.

**The boundary that keeps this from becoming a second envelope.** The rule is **the artifact versus the work**:
- **Here:** facts about the file as an artifact, obtained without interpreting the argument — byte hash, page count, format, and what the file's own front matter states about its identity and extent. A model may be used to *read* such a fact off the page (§7.11 and §7.13 both do); what makes the fact belong here is that it describes the artifact and does not change when the model is re-run against the same bytes.
- **The envelope:** what the model concludes about the *work* by reading its argument — thesis, scope, stated argument, reconstructed table of contents. These are interpretations, they are expected to improve as prompts and models improve, and their home is the artifact that gets regenerated.

Author, title and date sit on the artifact side of that line under §7.13, which is a move across the boundary and is intended: they are printed on the title page and stamped in the file's own metadata, and re-reading them does not depend on understanding the book.

**No source text.** Per DEC-23, this file carries no source text and no verbatim excerpts — not a title-page transcription, not a contents-page dump. It records values and short reasons. `data/` is gitignored, but the rule is about what the file contains, not where it lives.

The record is written once per source at intake and re-read, not recomputed, by later stages. Re-running intake on unchanged bytes yields the same `source_id` and overwrites the record with equivalent content; an edited source hashes to a new `source_id` and gets its own record, never inheriting a stale one.

### 7.13 Bibliographic metadata read at intake

`author`, `title` and `date` are read **at intake, from the PDF itself** — its embedded document metadata and its title page — and recorded in the source-metadata record (§7.12). A fourth field, `publisher`, and an identifier-based fast path for all four (below, issue #326) are recorded the same way. None of the four are produced by the envelope LLM pass. All four are threaded into every interrogation call as the note's source context (§7.15), so their quality now gates every answer record as well as every note's frontmatter.

**What this replaces, and why.** Measured across the current corpus:
- `author` and `date` are **null in all 30 envelopes**, and both propagate into every vault note's `source_meta` — roughly 17,000 notes advertising bibliographic metadata that is not there.
- `title` is **worse than null: it is fabricated.** In all 30 envelopes it is the filename slug, title-cased — `Mann Sources Of Social Power V2`, `Ugur Paramilitarism`, `Batatu Syrias Peasantry`. A wrong value that looks right is more dangerous than a blank, because nothing downstream can tell it from a real one.

The #268 measurement pass established that `pypdf` reads front matter reliably enough to support this path on most sources.

**How the title page is read: the model's judgment, not a positional rule.** An earlier design read the title page deterministically — the first non-blank line as the title, a year found within a short window of a copyright/publication marker as the date. It was measured against all 30 real sources (#285) and it did not work: of the 13 sources where it fired, it read the title correctly in **2**. The rest were an author's name mistaken for the title (`Sinisa Malesevic`, `Benjamin Thomas White`), publisher boilerplate, a series line, a journal header, a citation line, and truncated titles a length bound cut short. This is the same shape of failure §7.11 records for the retired deterministic holdings design: a positional/hand-tuned rule standing in for a reading judgment. The title page is now read by **the holdings check's own model call** (§7.11) — the same reasoning-on pass over the same cleaned front matter answers both questions together in one call, rather than a second pass over the same text. `date` is read this way too; it never reads embedded metadata (below).

**The whole title, not one clause of it.** A title page usually prints one title across two lines — a main title above its subtitle, with no punctuation between them — and the read returns both, joined as printed. A partial title is not a null: it is a well-formed string in a field called `title`, and nothing downstream can tell that its first clause is missing. Two things were needed for this to work (#316). The prompt has to say that the two printed lines are one title; and the title page has to reach the model **as printed**. It did not: the running-furniture strip (§7.11) counts a book's main title as a recurring header — which it is, on every body page — and then deletes it from the title page itself. Measured over the corpus, that removed the printed main title from the front matter of **7 of the 30 sources**, and on two of them (`ugur-paramilitarism`, `chouliaraki`) the main title reached the model on no page at all, so the read could not have been right at any model tier. The holdings call therefore shows the opening pages twice: cleaned, for the completeness judgment, and as printed, for this read. Measured on the six corpus sources with multi-line titles, five draws each: **6/30 draws correct before, 30/30 after**; over all 30 sources, one full pass went from 21/30 to 29/30. The `production_high` model tier was measured against the same baseline and did **not** fix it (20/30, and it regressed five sources), which is what pointed at the input rather than the reader.

**The cross-check: embedded metadata is verified against the title page, not merely trusted.** Embedded metadata is sometimes recycled from an unrelated file during conversion — one corpus source's embedded author and title name a different book entirely (#285). Nothing that only reads the embedded field can notice this; only something that also reads the actual title page can. So the same model call is told what the embedded metadata claims and asked whether it plausibly names the document it is actually looking at. An embedded value the model reads and confirms is recorded as before, with `embedded metadata` provenance; an embedded value the model reads and rejects is recorded as **unavailable**, never passed through — a wrong value with provenance is worse than an honest blank, which is the whole reason this cross-check exists. A model that made no comparison (no embedded value was present to check, or the check did not run) leaves the embedded value standing, exactly as it did before the cross-check existed — the check is additive, never a new way to lose a previously-working answer.

**The filename is never a source for these fields.** Not for `title`, not for `author`, not for `date`, not for `publisher`. A filename is an operator's naming convention, not the document's self-description.

**One contributor field, and an editor is recorded in it.** The record carries `author` and no role marker, so an edited volume's editor is recorded as its author. The identifier fast path already does this — where Crossref returns an empty `author` and an `editor`, the editor is used (`axial.bib_lookup`) — and `heydemann-2000` made it visible: Steven Heydemann edited *War, Institutions, and Social Change in the Middle East* and wrote its opening chapter. The distinction is real for a bibliographic record, and v1 does not carry it, because nothing downstream reads a contributor role: the vault takes `author` for a note's `source_meta` block and its display label, Gather takes it for the `(author, year)` pairs in a packet, and neither would behave differently given a role. A role marker is a future expansion, filed as #481 with the condition that would make it worth building.

**Identifier-based fast path (issue #326).** A source's front matter is also scanned — no network, `axial.identifiers` — for a checksum-valid ISBN-10/13 or a syntactically valid DOI; a corrupted check digit or an all-same-digit placeholder is dropped, never treated as a real identifier. A found identifier is resolved, with a disk cache keyed by the identifier so a re-run never repeats a request already made (`axial.bib_lookup`): an ISBN against Open Library's `/api/books` endpoint, a DOI against Crossref's `/works/{doi}`. This is the one network read in the pipeline, and it reads catalog metadata about the *file*, never the argument, so it does not breach charter Principle I.

**Gap-fill, not overwrite — the founder's third and final ruling on this contract.** The fetch **fills an empty field only**; it never overwrites a field the embedded-metadata/title-page read already resolved. Concretely, for each of `author`/`title`/`date`: the fetched value is used **only when the local field is currently `unavailable`**; a field already carrying `{value, provenance}` is authoritative and is returned byte-unchanged, provenance included — the file's own read wins over the catalog, always. `publisher` is always empty (no other reading mechanism exists for it), so it fills whenever a fetch resolves and the guard below passes. A filled field takes provenance `open_library`/`crossref`; a kept field keeps its existing provenance. The identifier itself is always recorded, for audit, whether or not it filled anything.

**Two safeguards gate whether a fill happens at all:**

- **Resolve-all-and-compare**, when the front matter carries **more than one distinct checksum-valid identifier** of the winning type (e.g. a hardcover/paperback/ebook block for one book, or a multi-volume work's own "also available in this series" listing). Every candidate is resolved (each independently disk-cached, still one attempt per identifier) and the resolved records are compared: if they plausibly describe the same work — the same author-overlap check described below, **and** a title-agreement check (one normalized title is a substring of the other) — they are different bindings of one book, and gaps fill from one of the agreeing records. If the resolved records disagree, the capture abstains: nothing fills, and the identifier field records `{type, value: null, abstained: true, candidates: [...]}` — every candidate found, kept for audit — using the same explicit-abstention shape §7.15 uses for an answer the passage does not support, rather than inventing a new sentinel vocabulary.
- **The same-work identity guard**, applied to whichever single fetch reaches this point: the fetched author must plausibly overlap the author intake already knows from embedded metadata or the title page (diacritics and "Last, First" vs "First Last" order are treated as the same person; no author already known passes the guard by default, since there is nothing to contradict). A failing guard fills nothing, not even an otherwise-empty field.

**Why gap-fill, not the overwriting design tried first.** Real-corpus measurement (read-only over `data/sources/`, live resolves against Open Library) found that all of `mann-sources-of-social-power-v1`'s candidate ISBNs — the shared series ISBN `9781107028654` and its siblings — resolve to *one* combined Open Library catalog record: a 4-volume box set whose `title` is the coarse series name, no per-volume distinction. Every candidate genuinely agrees with every other, so resolve-all-and-compare correctly finds no disagreement — but an overwriting merge would still have replaced each volume's own correct, already-known title with the box set's coarser one, and (for `mann-sources-of-social-power-v2`) overwritten a correct 1993 date with an earlier printing's 1986, reproducing exactly the seven-year-gap near-miss the whole mechanism was built to prevent. Gap-fill closes this structurally: every Mann volume already has a correct local author/title/date, so a fill never touches any of them — it only adds the shared, correct `publisher`, which the record never carried before.

**Unavailable is recorded, and is distinguishable from not-yet-attempted.** Each field is in exactly one of three states in the record, and the states are distinguishable by reading the record:
1. **a value**, with a recorded **provenance** naming where it came from — the file's embedded metadata, the title page, or the identifier lookup (`open_library`/`crossref`);
2. **unavailable** — the read was attempted and nothing recoverable was found;
3. **not attempted** — no read has run for this source.

A value is never invented to avoid state 2. Embedded PDF metadata is often junk (a producer string, an empty author, a file-creation date that is not the publication date); a value that fails a plausibility read is recorded as unavailable, not passed through.

**Where these fields now live, and what happens to the envelope's.** There is one answer downstream, not two:
- The **source-metadata record (§7.12) is the sole origin** of `author`, `title`, `date` and `publisher`.
- The **envelope no longer carries them.** They are removed from its locked shape (§7.3), which is `{source_id, thesis, toc[], scope, stated_argument}`.
- The vault's `source_meta` frontmatter block **keeps its five keys** (`author`, `title`, `date`, `thesis`, `scope`). The vault writer composes it from two places: `author`, `title` and `date` from the source-metadata record, `thesis` and `scope` from the envelope. Where a bibliographic field is unavailable, the note records it as unavailable rather than as an empty-looking value; a field the record does not carry at all is written as not-attempted. `publisher` and the raw `identifier` are recorded (§7.12) but not added to this frontmatter block.
- **A missing record is loud, never silent.** Since the record is the sole origin, a source with no record on disk cannot be written to the vault: the writer fails with a typed error naming the missing record, exactly as it already does for a missing envelope.

**The envelope's grounding guarantee is unaffected, and is strengthened.** §7.3 already forbids deriving `thesis`, `scope` or `stated_argument` from the title, the filename, or outside knowledge. Moving `title` out of the envelope removes the last reason the pass had to handle a title at all, so the envelope call reads source text and nothing else.

### 7.14 Best-of-N voting on the blind tag axes — STRUCK

> **STRUCK (D4).** The three-draw tag pass, `votes_by_pass`, the majority-vote layer and the per-axis abstention flag are retired with tagging itself. They bought a measured gain (`theory_school` 0.757 → 0.918, DEC-31) on a layer that produced bins rather than edges, so the gain does not survive the layer. v1 interrogates each note **once** (§3 non-goal 8); if draw variance turns out to matter, adding draws is a config change, not a design. Deleting the code is slice 03's job. One idea survives the strike, in a different form: an answer the model cannot give honestly is stated as an explicit abstention rather than fabricated (§7.15, D7).

### 7.15 The interrogation answer record

One call per note (§5 stage 6). One record per note, appended to `data/answers/<source_id>.jsonl`, keyed by `chunk_id`. This is the contract slice 02 implements.

**Context supplied to the call (D6).** Exactly this, and nothing else:
- the note's `text`, verbatim from the chunk artifact (§7.7);
- its source's `author`, `title` and `date` from the source-metadata record (§7.13);
- its source's `thesis`, `scope` and `stated_argument` from the envelope (§7.3);
- the chapter it sits under, from the envelope's reconstructed `toc`, and its own verbatim section heading from the chunk record;
- the domain frame's example lists and their definitions (§7.1), supplied as examples of the kind of answer wanted, never as a menu to choose from.

**No web, no external lookup, and no reliance on what the model knows about the book** (charter Principle I). The passage and the context above are the only inputs. The prompt says so, in the same terms §7.3's grounding rule uses for the envelope.

**The questions (D6).** Fourteen, each producing one field:

| Field | Question |
|---|---|
| `about` | What is this passage about? Multi-valued. |
| `claim` | What is being claimed, in one sentence. |
| `move` | What is this passage *doing* in the argument? Not "evidence" but "conceding a point in order to narrow it". |
| `ranges_over` | What does the claim range over? |
| `stops_holding` | Where does the author say it stops holding? |
| `position_of` | Whose position is this? The holder only — the author's own, a named scholar, a named school. |
| `position` | What *is* that position, in the passage's own terms? One sentence stating the stance itself. Asked even when the holder is the author. |
| `arguing_against` | Who or what is it arguing against? Multi-valued. |
| `names` | Every named thing the passage names, each `{name, kind}`. `kind` is usually one of person, country/state/place, institution/group, movement/religion, period, event, concept, work, figure, table — offered in the prompt, not enforced; a name that fits none of them gets the model's own word. |
| `citations` | Who does it cite, and is each citation **support**, **foil**, or **authority**? Each is `{cited, stance, about}`. |
| `mechanism` | What causes what, in what order. |
| `evidence` | What evidence is offered. |
| `comparison` | What comparison is made, stated or implied. |
| `defines` / `uses` | What is defined here, versus merely used. |
| `concedes` | What the author concedes or hedges. |
| `assumes` | What it assumes without saying. |

**`position_of` and `position` were one question, and the corpus is a permanent mix of both frames (issue #496).** Until frame 0.2, `position_of` asked "whose position is this?" alone and got whichever of the two answers the model reached for. Measured over the 6,148 records on disk: 4,693 carry a non-trivial answer, 76% of those say some variant of "the author" (informative for attribution, useless for comparison) and the other 24% name a school instead (the reverse). Nothing downstream could tell the two cases apart. `position_of` is unchanged in name, wording and meaning; `position` is the new field, and the `theory_school` examples (Appendix E) moved onto it, since a school label is what a position *is*, not whose it is. `position_of` has no example axis, which is correct — there is no vocabulary of position-holders.

**A full re-interrogation is not planned; a targeted backfill of `position` alone is (issue #697).** Interrogation is ~$34 a corpus pass, so the split itself takes effect only for sources interrogated from frame 0.2 onward — that part is unchanged. But the 6,148 records written under 0.1 do not just lack a field, they hand every reader of `position_of` a **holder name** where §5's read layer promises a **stance sentence** (`query/reader.py`'s `stated_position()` falls back to `position_of` on an absent key, by design). Issue #697 closes that gap without paying for a full re-run: one question, `axial.position_backfill`, asked once over every note that lacks `position`, keeping the frame's `theory_school` examples and showing the note its own already-recorded `position_of` so the two stay consistent. It patches the field onto the existing record in place — `frame_version` is untouched, so a backfilled record still reads `frame_version: 0.1` and carries `position` all the same.

A record written under frame 0.1 and never backfilled carries `position_of` and **no `position` key at all**; a record written under 0.2, or backfilled under #697, carries both. `frame_version` on each record says which frame produced its *other* sixteen answers, but **a consumer branches on key presence, not on that string** — another domain versions its own frame independently, and #697's backfill is exactly the case that string cannot describe. The rule for every reader is: use `position` when the key is present, fall back to `position_of` otherwise. A field a record does not carry is excluded from that record's denominator in the abstention and collapse reports, never counted as answered.

`citations` is the field with no v0 ancestor and the highest expected yield. Academic prose carries explicit references to other scholars, these books cite each other, and no pass ever looked for them. They are author-stated cross-book edges available from the first reading. **The harvest will be partial and that is expected, not a failure**: some in-text references come out of the scan mangled, the furniture cleaner drops some footnote markers, and most of what these books cite is not in the corpus. An out-of-corpus citation is still a name worth keeping — it says who the author is arguing with — but it cannot become an internal link.

`names` is where the deleted cross-reference pass's job lands (D5). A figure or table named in the prose is a nameable thing with `kind: figure` or `kind: table`, harvested exactly like a person or a place, and it gets a name page like any other name (§7.17).

**Abstention is explicit (D7).** Every answer is given **only** from the passage. Where the passage does not support one, the model says so plainly rather than reaching. Concretely, every field is in exactly one of three states, and the states are distinguishable by reading the record:
1. an answer;
2. the explicit abstention `not-in-passage` — written either as that bare string or as `{"not-in-passage": "<one-clause reason>"}`, which is where the "cannot judge between X and Y" case is said: the passage bears on the question but does not settle it. Both forms are structurally distinct from every answer, which is a string, a list, or an object with other keys. A **multi-valued** field abstains the same way, with the bare string; the reader also accepts either form alone inside a one-element list, since that is the shape a model reaching for a list-valued abstention actually produces, and reading it as an answer would both under-report abstention and mint `not-in-passage` as a name in Reconcile's inventory (§7.16);
3. absent, meaning the call did not complete for this note (which is a failure, not an answer, and is recorded as one).

A guessed answer is worse than an abstention, because nothing downstream can tell it from a read one. This is the same rule §7.13's three-state bibliographic contract holds for a different reason.

**An empty list is an answer, not a blank.** On the multi-valued fields (`about`, `arguing_against`, `names`, `citations`, `defines`, `uses`), `[]` says the passage names none of that kind of thing — a read, not a refusal to guess — and it is recorded verbatim, never normalised onto `not-in-passage`. It is the natural JSON for the common case, and treating it as malformed is expensive in a way worth stating: the re-ask carries no error feedback, so the model repeats the identical response until the budget is spent and then **the whole note is discarded over one field**, permanently, since a note carrying any record is never re-sent. A real 10-note probe lost one note that way.

**Examples must not capture the answer (D8).** This is the single biggest regression risk in the feature: if the interrogation answers in the frame's vocabulary, v1 has rebuilt tagging with more values and failed silently. Three rules hold the line.

1. **The free answer is asked for first**, in the model's own words, before any example list is presented for that question.
2. **The nearest example is a separate, secondary, marked field.** Where a question has examples, the record carries `<field>` (free text) and `<field>_nearest`, shaped `{example: <id> | null, fit: close | loose | none}`. `none` and `null` are ordinary answers.
3. **Code never bridges the two.** No normalization of a free answer onto an example, no rewriting either way, no filling `<field>` from `<field>_nearest`. They are recorded as given.

**The collapse check.** Slice 02 measures, over the sample and again over the full run, two shares per example-bearing field, both exact-match after casefolding and whitespace collapse: the share of free answers string-equal to **any** of that question's example values, and the share string-equal to that record's **own** `<field>_nearest.example`. Abstentions are excluded from both denominators; an abstention is not a collapsed answer. Both numbers are reported. A field whose free answers are overwhelmingly verbatim example strings means the ordering has failed and the pass is rebuilding tagging through the back door; that is a stop-and-fix, caught at the 50-output sample gate before the corpus is paid for. No threshold is asserted here, because none has been measured; the check exists so the failure is visible rather than silent.

**Per-note fault isolation.** A single note's call failing — a moderation refusal, malformed JSON surviving the retry budget, a transport error — is recorded against that `chunk_id` with its reason and skipped; the source continues with its remaining notes. A source that answered **nothing** still fails loudly rather than reporting an empty success, and it keeps failing on every rerun until the cause is fixed: the rule is read off the artifact (no answer records, at least one failure record), not off one run's own counters, because the path an operator takes after seeing the error is to run it again — and a rerun re-sends no note, so it fails nothing itself and would otherwise report success with an empty answer set. Skips are not failures: a source whose every note the garble backstop dropped legitimately has no answer records. At the end of a source, the pass checks that answered-plus-failed-plus-skipped equals the chunk artifact's own count for that source and raises rather than returning a silently short result. This is the v0 tag pass's reconciliation discipline kept intact; only the vocabulary machinery around it is gone (§7.1).

**Record shape.** One JSON object per line: `{chunk_id, source_id, section, pass, model, frame_version, answered_at, answers: {...}}` where `answers` carries the fields above and `section` is the note's own verbatim heading, carried as provenance the way the chunk record carries it. Appendix H shows the same content as it lands in a note's frontmatter.

**Three record kinds share the file**, each keyed by `chunk_id` and told apart by which key it carries: an **answer** record (`answers`), a **failure** record (`failure_reason`, state 3 above), and a **skip** record (`skip_reason`, a note the §7.8 garble backstop dropped before any model call). One artifact per source, so the reconciliation below is a read of one file and a skip can never again be a silent loss. The file is also the resume point: a note already carrying any of the three is never re-sent to the model.

### 7.16 Name inventory, alias map and the index

Reconcile (§5 stage 7) runs over **names, not notes** (D10). Three artifacts, under `data/names/`.

**1. The inventory (`inventory.jsonl`).** One record per distinct surface form the interrogation returned in `names`: `{surface, kind, count, chunk_ids[]}`. Nothing is merged here. If the corpus gave a surface more than one `kind`, the record keeps the most frequent one, ties broken by first occurrence: the joined vocabulary (§7.15) already removed the collisions that carried real information, so what a tie discards is a distinction the vocabulary itself declines to make.

**A citation is not a name page, and the inventory is a filtered record rather than a lossless one (issue #508, founder decision 2026-07-30).** This section used to say the inventory was built from `names` and `citations` and was "the complete, lossless record of what the corpus said". Both halves are now false, deliberately. The `citations` arm alone contributed 22,430 surfaces, 13,661 of which existed only because of it: 17.5% of the inventory, one wiki page each. That residue is not back-matter scrapings. Measured by section, 89.9% of chunks are body prose, and 9,587 of the citation-shaped page names came from body-only chunks against 957 from back matter. It is what a social-science monograph does in every third sentence. `citations` keeps being recorded on the answer record (§7.15) and Phase B keeps reading it as evidence; it no longer seeds a name.

**The cut set.** A surface matching any row below leaves the name space. A page disappears only when **every** surface that would have been its member matches, which the per-occurrence filter gives by construction: one surviving occurrence keeps the entry, and one surviving member keeps the page.

| | rule | surfaces | pages if cut alone |
|---|---|---:|---:|
| **A** | arrived only via `citations[].cited`, never via `names[]` | 13,661 | 9,701 |
| **B** | every occurrence sits at or after its own source's back-matter boundary | 8,110 | 5,292 |
| **H** | carries an author-year citation (`(1990)`, `, 1990`, `et al`) | 5,995 | 3,787 |
| **F** | a date or a date range (`1917-1918`, `6 June 1975`, `March 1963`) | 1,012 | 959 |
| **D** | apparatus pointer, `is_apparatus_pointer_shaped` | 746 | 677 |
| **C** | bare numeral or century, `is_numeral_only_surface` | 623 | 501 |
| **E** | locator, `is_locator_shaped` | 441 | 431 |
| **G** | page, volume, `no.`, `ibid`, `op. cit.` reference | 140 | 98 |
| **P** | `source N` / `reference N` / bare bracketed `[N]` pointer | 661 | — |
| **S** | the literal abstention sentinel `not-in-passage` (§7.15) | 1 | 1 |

Every row but B was measured against the 78,198-surface / 62,704-page layer that preceded the cut; **row B was measured after those nine landed and the corpus was rebuilt** (61,612 surfaces / 49,674 pages), so its two numbers are the right shape but not comparable in size to the rest of the column. Rows overlap, so a union is never the sum of its rows.

Measured over the live layer, rows A and C-S: the index falls from 62,704 to 50,395 pages (−19.6%), 12,309 pages removed entirely, 2,010 surviving pages losing members and so re-keying their Gather decision, and 48,385 untouched. **The 10+ casualties are the point, not the risk**: row A's 96 are `34`, `[34]`, `54`, `[23]`, footnote reference numbers with up to 28 member notes each; row D's 17 are `Chapter 5` (n=52) and `Chapter 4` (n=50); row S is the interrogation's own abstention sentinel, which leaked out of `citations` and took a page with 24 member notes.

**Every rule is enforced in one place** — `axial.names.iter_name_occurrences`, where the answer record is read — so a newly ingested source is filtered by construction on the next inventory build, with no incremental-specific code path. **The pass stays LLM-free**: row A is the absence of a field read, row B is a position read off the structural tree §7.7 already cached, and every other row is a shape test carrying no tunable constant: each names the near-misses it deliberately leaves alone (`10 Downing Street` for C, `Chapter VII of the UN Charter` for D, `1948 War` for F, the surname `Page` and `Volume One` for G, a parenthesized acronym for H, `Sources of Social Power` for P). Row S reuses §7.15's own `is_abstention`.

**Three further classes measure well on page count and are refused.** A lowercase multi-word phrase would remove 6,486 more pages and would take `negative sovereignty` (n=47), `cumulative bureaucratisation of coercion` (n=33) and `social citizenship` (n=27) with them: those are the concepts the product exists to argue about. An 8+-token rule (1,845 pages) reaches real article titles, a legitimate `work` name. An opens-with-an-article-or-preposition rule (839) carries the same risk for a smaller prize. In each case the rule is cheap and the collateral is real content, which is the trade this cut set refuses everywhere.

**Row B is a boundary per source, not a judgment per heading (issue #511).** A book's back matter is *where* it sits, not what it is called. `axial.names.back_matter_section_orders` reads the structural tree §7.7 already cached for that source, finds where its back matter starts, and every section from there to the end of the book contributes no names. Two anchor families set the boundary, and each earns its asymmetry from the corpus:

- **the first index anchor.** An index is terminal. Across all 31 cached trees the earliest index anchor sits past 91% of the way through the book, and there is no interior one anywhere.
- **the last bibliography anchor.** A bibliography is routinely interior: an edited volume ends every chapter with its own `References` (17 of them in one), and Mann's volumes end every chapter with a `Bibliography`. Only the last one can be a boundary.

The boundary is the earlier of the two, then extended backwards over the contiguous anchors before it — which is what catches a bibliography a running header split into thirty consecutive one-page sections. Matching drops digits and punctuation first, so `90 References`, `330 ● Index` and `Bibliography Z 231` read as their anchor, and it accepts docling's per-glyph spacing (`I N D E X`, `S E L E C T B I B L I O G R A P H Y`) and OCR's word splits (`I NDEX`).

**The sections this actually removes carry no anchor word at all**, which is the whole reason position beats vocabulary: bibliography subsections (`Books`, `Sources in Other Languages`, `IV. Books and Book Chapters`, and Tilly's bibliography-by-chapter, whose eight sections are titled exactly like his eight chapters), running-header fragments (`304 ●`), index entries promoted to headings (`Peres, Shimon, 318-19`, `Dahomey women warriors, 281`), contributor lists, and publisher series ads. `axial.chunk` already drops a section whose title is *exactly* `index`/`bibliography`/`contents`/`references`, so the clean anchor is usually still in the tree while every section that reached the name space is garbled or a fragment.

**Endnotes are kept, and here that holds by construction rather than by asking for it.** Endnote sections interleave per chapter mid-book, nowhere near either boundary. So does the argument: `CONCLUSION`, `PROLOGUE`, `The Structure of the Book`, `Part III` and `DURKHEIM` are all interior, and a boundary rule cannot reach an interior heading. Front matter is deliberately **not** cut: the same trick fails there, because `contents` recurs mid-book (Wimmer's appendix has one at 57% of the way through), and the prize is small.

Measured over the live layer: 8,110 surfaces dropped of 61,612 (13.2%), the index from 49,674 to 44,382 pages (−10.7%), 5,292 pages removed, 2,539 surviving pages losing members, 41,843 untouched. It excludes 234 of 6,166 notes (3.8%), and finds a boundary in all 31 sources. Of the 1,824 pages at 10+ member notes, 2 disappear (`Free Press`, `Journal of Conflict Resolution`), 1,631 stay at 10+, and 191 fall below the floor — those are `Yale University Press`, `The American Political Science Review`, `I.B. Tauris`, `New Haven`, publishers and journals whose note counts were bibliography entries. A handful are real scholars who were only clearing the floor on the strength of their own bibliography lines; their surviving count is the honest one.

**The acceptance was the cut list read book by book, not the aggregate** — every section the boundary removes, with what it contributed. That is what settled it, the same lesson as issue #472, and it is reproducible with zero model calls from `scratchpad/validate_511.py --diff`.

**Two earlier attempts asked a model what each heading meant, and both failed.** They classified the corpus's 2,813 distinct `section` headings once, in six sorted batches (#164's classify-once shape). The failure was per batch, not per heading: front-matter labels ran 0.0%, 1.6%, 15.8%, 3.5%, 2.5%, 3.5% across the six, one batch carrying 74 of 125. Round 1 miscut 11 endnote headings; round 2 fixed those and miscut chapter titles of the argument (`EXPLAINING THE EXPANSION`), author names (`DURKHEIM`) and OCR damage (`Fohn A. Hall`) instead. Round 2 improved every aggregate over round 1 while the content loss got worse. Both classifications are kept verbatim under `data/logs/2026-07-30-validate-508/`. The mechanism that shipped needs no call, so the whole class of failure is gone: contamination cannot cross books when the unit is one book, and a bad boundary is one visible book rather than a slice of the alphabet.

**A locator-shaped surface was scoped by source rather than merged by string identity (issue #445), and row E now removes it before that rule can apply.** A figure, table, map or similar cross-reference (`^(fig\.?|figure|table|map|chart|graph|plate|box|diagram|appendix)\b`, case-insensitive) is book-relative: "Table 4.1" in one book and another book's own "Table 4.1" are not the same thing, and keying the inventory by exact surface string collapsed them into one node, correct for `United States` and wrong for a locator. The scoping rule is unchanged in code — a locator spanning more than one source would still become one entry per source, rendered `"<surface> (<source_id>)"`, and Reconcile's fold would still refuse to merge two of them back together — but a locator is not a name at all under row E, so nothing reaches it. The rule stays rather than being deleted with this change; removing it touches Reconcile and Materialize both, and that is a separate piece of work.

**A bare page number, a plain century and an apparatus pointer are cut at inventory time, not at the model call (issue #508, superseding the 2026-07-29 fixes).** Both predicates shipped as gates at the point Reconcile and Gather ask the model something, and both left the surface its own unmerged canonical node, so each still had a wiki page: `13` with 18 member notes across 12 books, `Chapter 4` with 46, `Footnote 36` with a written disagreement about nothing (`data/logs/2026-07-29-gather-stratified-sample/`). Cutting at inventory time is what removes the page. The predicates themselves are unchanged: `^[0-9]+(st|nd|rd|th)?( century)?$` for the numeral, and for the pointer a shape test over `LOCATOR_PATTERN`'s own label set plus `chapter`/`chap.`/`ch.`/`footnote`/`endnote` (never bare "note" — "Note on the State" is a real name), matched only when the label is followed directly by a digit or one of the English cardinal words one through twenty. That digit-or-word requirement is what lets "Chapter of Sainte-Chapelle", "Table of Ranks" and "Chapter VII of the UN Charter" survive, along with any bare-letter appendix or table. The call-time gates are gone: with nothing of that shape in the inventory, a second gate could only ever report zero.

**2. The similarity view, LLM-free.** The inventory's surfaces are embedded and clustered, and the run **reports the distribution**: cluster count and size distribution at a few candidate tightnesses, the largest clusters with their members, and a sample of borderline pairs. This is a **viewing aid**, and it exists so merge aggressiveness is chosen by looking rather than guessed. It reuses the existing embedding path (`src/axial/distill/embed.py`, §12); it decides nothing.

**A surface form already in the previous build keeps its cluster label unchanged, rather than every build re-fitting HDBSCAN over the whole corpus (issue #677).** Adding a handful of books to a 34-book corpus (#623) moved 5,143 of 13,900 merge batches (37%) — not because any of those judgments changed, but because a full re-fit reshuffles which cluster everyone sits in, and Reconcile's own decision key is a hash of the batch's rendered membership. `axial names build` now persists the fitted transform chain (L2-normalise → `StandardScaler` → PCA) and the fitted `hdbscan.HDBSCAN` clusterer (`prediction_data=True`) alongside the manifest, via `joblib` — the library's own convention for a fitted estimator, not a bespoke format. The next build, when the model name, `pca_components`/`min_cluster_size`/`min_samples`, and the installed `hdbscan`/`scikit-learn`/`numpy` versions all still match what the persisted fit recorded, does not re-fit: every surface form the previous build already saw keeps its label and its vector (no re-embedding either), and only the surface forms new to this build are placed, via `hdbscan.approximate_predict` against the persisted fit. Any mismatch — a moved dial, a different embedding model, an incompatible library version, or `--recluster` — falls back to a full re-fit, reported on stderr, and refreshes the persisted artifact; a full fit is never unavailable.

**A raw `approximate_predict` result is not safe to trust as-is.** Measured directly against this corpus's own settings (`cluster_selection_method="leaf"`, `allow_single_cluster=True`, PCA 10): a point that genuinely belongs to an existing cluster predicts in at median membership strength 0.80, but a genuinely new cluster's 20 points had 19 of them swallowed into an unrelated existing cluster at median strength 0.29 — worse than useless, since a noise or single-member prediction produces no merge batch at all, so a swallowed new cluster's names would silently attach to an already-decided judgment and never get asked about on their own. A prediction is trusted only when its strength clears that cluster's own fitted floor — the minimum `probabilities_` HDBSCAN gave its own training members of that cluster, derived from the fit rather than a hand-tuned constant. Anything that does not clear the floor, or predicts as noise, falls into a **residue**, which gets its own fresh HDBSCAN fit at the same dials, its labels offset above the existing maximum so ids stay disjoint. Existing labels are never renumbered.

**Four counters make the savings legible in the pass's own summary** (`units_total`, `units_reused`, `units_asked`, `units_asked_touching_new`): `units_asked` is how many entries this run actually had to place — new plus residue — and `units_asked_touching_new` narrows that to the ones involving a source absent from the previous build's own manifest, which is what turns "N model calls happened downstream" into "how many were actually about the new books" without a scratch script over run logs. Running the pass twice with nothing new reports `units_asked: 0`.

**3. The alias map (`alias_map.json`) and the index.** The model makes the merge calls, with the clusters as hints, one call per cluster (`reconcile`, §7.9) — a cluster large enough to threaten the request is split across a few calls, which is a limit on prompt size and nothing else. The output is data: `{version, generated_at, nodes: [{canonical, kind, aliases: [...]}]}`, the same shape `polity_canonical.yaml` already uses, which is what seeds it (§7.1, D9). **The surviving `canonical` set is the index**, written alongside the map as `index.json` — the list Materialize (§7.17) writes one name page per entry for. Because the map is data and the inventory is rebuilt from the answer records on every run, every merge is **reversible and re-runnable**: re-reconciling at a different tightness rewrites the map and the name pages, and re-reads not one source and re-interrogates not one note. Nothing else on disk records that a merge happened, so deleting or editing one node undoes exactly that merge.

**The canonical is the seed's spelling, then the most-mentioned spelling the model actually chose, then the most-mentioned spelling (issue #642).** A merge node the model returned with no aliases folded nothing, so it is not a preference and does not enter that second round — read as one, it let `Asʿad`, mentioned once, name the page holding Hafiz al-Asad's 110 notes. And where the model really did choose more than one canonical and those later land in the same group, mentions decide before the size of the batch each one won, so `Ba'th Party` (20 mentions) names the party's door rather than `Syrian Ba'ath party` (1 mention, but 4 aliases in its own batch). Measured over the corpus of record: 102 of 49,674 pages change name, every one of them toward a spelling the corpus uses more.

**A canonical name is always a surface form the corpus said.** The seed may fold two surfaces together whose curated spelling the corpus never used; in that case the fold stands and the canonical is still elected from the group's own members. Reconcile merges names; it never mints one.

**Every decision is persisted, and that is what makes the pass reproducible.** `reconcile` samples at temperature 1 (§7.9), so the model does not repeat itself on a re-ask. Each cluster's answer is therefore written to `merge_decisions.jsonl` as it is produced, keyed by a content hash of the cluster's own **rendered** member list. Re-running reproduces the same merges by reusing the same recorded decisions; moving the tightness dial re-decides exactly the clusters whose membership changed; and an interrupted run resumes rather than paying twice.

**The merge call is joined to evidence the inventory already has (issue #449).** A bare surface form and its kind do not contain enough to tell `Adam Smith` from `Anthony D. Smith`, or two same-named authors apart. Each inventory entry already carries the `chunk_id`s it came from, so the merge prompt is unconditionally joined to **source provenance** — which book(s) a surface form appears in, at zero extra file I/O since the source id lives inside its own `chunk_id`. Two costlier cumulative tiers (+ section titles; + a short passage window) were built alongside this one so the founder's own measurement run could compare all three against the bare-name pass; the measurement (issue #453, `docs/DECISIONS.md` DEC-51) found source provenance was the only one worth keeping, so the other two are gone rather than kept as a permanent dial. Evidence rides inside the one rendered member line the prompt shows and the parse reads back, never a second echo format of its own. Consistent with `docs/DECISIONS.md`'s DEC-206 (withhold the scores): the evidence is descriptive (source provenance), never a similarity number a candidate stage computed — showing a score would anchor the model to the rule's own answer instead of an independent read.

**Because the rendered member line is what the decision log's key is drawn from, a batch already decided without evidence is a different decision, not a reuse** — the value of attaching evidence would otherwise never reach an already-decided corpus. This is also a rollout hazard: the first run with evidence attached makes every previously-decided (bare, pre-#449) cluster look, by key, like an undecided one, which would silently re-ask the whole corpus rather than a deliberate choice. Reconcile guards this by bare membership — every decision record keeps the surface forms it was actually about, independent of whether evidence was attached — so a cluster already decided without evidence is found and reported by count, and the run refuses to spend on it until `--confirm-reask` says so. Confirming purges exactly those superseded records (never the whole log) and re-asks them with evidence attached, same as any other pending batch.

**The merge call can say it cannot tell, and that is a third outcome, not a default (issue #450).** Before this, an unplaced surface form looked identical whether the model had confidently judged two names distinct or had simply been forced to guess — nothing on disk told the two apart. The response carries a top-level `"undecided"` list alongside `"nodes"`: a surface form the response places there is **escalated**, and the parse keeps it distinct from a surface form the response never mentions at all, which is still simply unplaced (except in the exactly-one-node case, next). `alias_map.json`'s shape (above) does not change and never gains a field for this — an escalated surface **stands alone**, exactly as an unplaced one always has, because D10's asymmetry still holds: splitting loses less than fusing. What changes is that the decision persisted to `merge_decisions.jsonl` now carries an `escalated` list, so the rate is measurable and the escalated surfaces are addressable by name without re-asking anything, and `merge_manifest.json` carries a corpus-wide `escalated_surfaces` count so the rate reads off the manifest without re-parsing the decision log. A response that escalates every member of a batch, placing nothing in `nodes`, is a real judgment and is not re-asked as if it were malformed noise; a response that places nothing in either list still is.

**A response that reduces to exactly one node is the model saying the whole batch is one entity, so a member the node omits is read as its alias, not left to split off as its own page (issue #504).** The prompt's own contract asks for every member exactly once across `"nodes"` and `"undecided"` together; when only one node comes back, a member mentioned in neither is that contract half-followed, not a considered "these are different" — the neighbouring failure (a response that places *none* of the batch) was already rejected outright and re-asked, so accepting a response that places *some* and silently dropping the rest was the stricter case sitting on the wrong side of the line. Scoped tight to the unambiguous shape: two or more nodes is a real partition the model drew, and an omission there is untouched, still simply unplaced (D10's asymmetry). A surface form the response explicitly escalates is also untouched — "cannot tell" is a real judgment, never swept into the sole node alongside it. Because `merge_decisions.jsonl` is keyed on the batch's own rendered members, this fold applies to an already-recorded decision exactly as it applies to a fresh one: `axial names merge` re-reads every existing record through it when building the map, so a decision from before this fix folds on the very next run with no model call and no change to its `batch_key`.

**A batch that never once places any of its own surface forms across the whole re-ask budget is response noise, not a judgment, and is never confused with escalation (issue #469).** `complete_json` re-asks the same prompt (no sleep) up to its bounded attempt budget on either an unparseable body or a response `parse_merge_response` cannot place any batch member in; if every attempt fails that way, the batch is never written to `merge_decisions.jsonl` at all — the exact same treatment it would get if the model had never been asked, so a later run retries it rather than treating the failure as a standing verdict. What was missing was durability past the run's own stderr: `merge_failures.jsonl` (alongside `merge_decisions.jsonl`, under `data/names/`) records each such batch's members and the failure reason as it happens, append-only and never read back by `reconcile` itself, so which surface forms a run gave up on is legible after the run ends without ever being able to count toward `escalated_surfaces` or appear in `axial names escalations` — those two only ever read a *successful* parse's `escalated` list, so this separation needs no gate of its own to hold. `parse_merge_response`'s own "placed none of the batch" error also carries the raw response's length and its first/last 200 characters, the cheapest on-disk discriminator between a truncated body and a well-formed answer to the wrong prompt.

**An escalation is a deferral, not a write-off, and `axial names escalations` is where an operator sees the shape of it (issue #461).** The manifest's `escalated_surfaces` count says how many, not what: `axial names escalations` reads `merge_decisions.jsonl` and `inventory.jsonl` read-only and, for every escalated surface, lists the co-members it was proposed with (that decision's own batch, minus itself), the source book(s) it appears in, and a per-kind count across the whole set — enough to judge whether the escalated set is one problem or five, and the same evidence a later "re-ask exactly these" pass would need. Deliberately no queue, no resolution state, and no write path: escalating stays a thing the model said, never a status an operator sets.

**Start loose, tighten by inspection.** There is no right aggressiveness up front. "State formation through war" and "bellicist state building" must meet; two genuinely different ideas must not. The loop is: reconcile, materialize, look at the graph, tighten. That is why the inventory and the view are their own slice, separate from the merge. The dial is the clustering tightness the merge asks about — `names.merge_min_cluster_size` / `names.merge_min_samples` in `config/pipeline.yaml`, the same two settings the similarity view sweeps and reports, so the founder moves it by reading that report. It is never a value in the prompt: the prompt states the judgment and the model makes it; how much is put in front of the model at once is config's business.

**The merge reuses the similarity view's own fit rather than re-running it at the start of every invocation (issue #458).** `similarity_manifest.json` already records the tightness and `pca_components` the view was built at, alongside the cluster labels themselves; when a merge run's own settings match, it reads those persisted labels straight back, at zero HDBSCAN cost. Only a moved dial — or an explicit `--recluster` — pays for a fresh fit, exactly as before. Because a full-corpus fit is a 10+ minute step, whichever path a run takes it says so on stderr as it happens: which one it took and why, and, when it does re-fit, an elapsed-time heartbeat while the fit runs rather than nothing at all until it returns.

**The merge pass reports the same four counters, over its own batches, not the similarity view's entries (issue #677).** `units_total` is this run's own cluster-batch count (HDBSCAN's plus candidate generation's, before `--limit` trims anything); `units_reused` is how many of those already had a decision on `merge_decisions.jsonl` before this run's worker pool spent a single call; `units_asked` is the rest — every batch not yet decided, whether or not `--limit` actually lets the pool reach it this run; and `units_asked_touching_new` narrows that to batches whose members touch a source absent from `merge_manifest.json`'s own `source_ids`, read from the manifest this run is about to overwrite, *before* that write happens — the same field name `axial names build`'s own manifest and `axial.argmap.build`'s pin manifest already carry, for the same reason. Source ids are read off the evidence join issue #449 already built (`build_evidence_index`'s own `chunk_id → source_id` resolution), never re-derived. Absent a prior manifest (a first-ever run), every asked batch counts as touching new. Running the pass twice with no corpus change reports `units_asked: 0`.

An unmapped surface is never dropped. A surface that reached the inventory and that no cluster and no merge call folded is its own canonical node with no aliases. A surface the cut set removed never reached the inventory, so it has no node at all.

**Candidate generation recovers what clustering's own looseness misses (issue #446).** Loose clustering (above) is tuned to never fuse distinct entities, and that has a recall cost: a name and its variant routinely land in different clusters, so no merge call ever sees them together and both survive as separate canonical names. A second, deterministic, LLM-free step proposes the missing pairs as additional cluster-shaped batches, fed to the exact same merge call — it decides and merges nothing itself, only widens what the model is asked about. Three rules, each an exact string shape with no similarity threshold: an initial forename against the one full forename sharing its surname and first letter (`C. Tilly` / `Charles Tilly`); a bare surname against the one full name sharing it, both `kind == person` (`Abercrombie` / `Nikolas Abercrombie`); and a parenthesized acronym against its own standalone inventory entry (`AANS` / `Autonomous Administration of Northeast Syria (AANS)`, issue #498, D2 — below). Every rule refuses outright — proposes nothing — the moment a short form has more than one candidate (`R. Cohen` against both `Robin Cohen` and `Roger Cohen`; bare `'Ali` against seven distinct people; `SDF` against both `Marxist Social Democratic Federation (SDF)` and `Syrian Democratic Forces (SDF)`), rather than guessing.

**A parenthesized acronym is a candidate, never a string fold (issue #498, D2).** Unlike the case/whitespace/punctuation fold below, an acronym is not folded straight into the alias map: `ABC` resolves to `Al-Ahram Beverages Company` in this corpus and need not everywhere, so whether the two sides are the same entity is a judgment, not a string-shape fact. The rule is a shape test, stated once: a run of two or more bare uppercase letters, alone in parentheses, inside a surface form (`Autonomous Administration of Northeast Syria (AANS)`) — a lowercase word, a multi-word parenthetical, a bare year, and a page locator all fail this shape. The pair is proposed only when the acronym also exists as its own standalone surface form elsewhere in the inventory; an acronym the corpus never writes bare (`AANES`) has nothing to pair with and is silently skipped — that stopword-skipping initialism tier is deliberately out of scope (recorded against issue #498 as the smaller half: it reaches only strings absent from the inventory, while this rule reaches every acronym the corpus already writes both ways). The pair goes through the same merge call and the same evidence check (issue #449) as any other candidate, and because that decision is unioned into the alias map alongside every other decision, a chain of separately-decided pairs collapses transitively: `AANS` folding onto its parenthetical-bearing alias, which a real HDBSCAN cluster already folded onto the full spelled-out canonical, lands all three on one page. That transitivity is exactly why the rule refuses an acronym carried by more than one distinct surface form (measured on the live corpus: 26 of 165 multi-carrier acronyms, and two real fusions before the refusal shipped — `SDF` above, and `CDR`, fusing Rwanda's `Coalition for the Defence of the Republic` with Lebanon's `Council for Development and Reconstruction`). The acronym's own standalone node is a hub in the union: with two or more candidate expansions, proposing even one pair would let the model's fold of that ONE pair drag in whichever other expansion a separate decision also unions onto the same acronym, fusing two entities no call was ever asked to compare — the union does the fusing silently, not a bad model answer. Refusing keeps the hub down to at most one candidate edge, so the transitivity above still holds for the single-expansion case it was measured on, and never chains two unrelated ones through a shared acronym. The rule matches on that same fold (`fold_groups` runs upstream of every candidate family, issue #463), not the literal acronym string — a bare acronym is often already unioned with its own dotted or spaced punctuation variant before this rule ever runs (`CIA`/`C.I.A.`), so it looks for whichever spelling actually survived that fold rather than assuming the bare form is still its own entry (measured on the live corpus: 8 of the most-cited acronyms, including `CIA`, `PLO` and `UN`, were silently missed before this fix, because their standalone entry had folded onto a punctuated form).

**Case, whitespace and punctuation are folded upstream of every candidate source and of clustering itself, never asked about as a candidate (issue #463).** A separate rule used to propose surface forms identical once casefolded and whitespace-collapsed as a candidate cluster, and measured on the corpus of record the model refused 295 of roughly 305 of them: whether two strings that differ only by case are "the same thing" is not a judgment, so widening what the model is shown cannot fix a refusal. The fix moves earlier: every surface form is folded (case, whitespace, and punctuation — a hyphen to a space, since this corpus's compound names and transliterations vary between hyphenated and spaced spellings of the same words; everything else, including a leading `#`, to nothing) before clustering runs and before any candidate family runs. A group of surface forms identical under that fold is unioned directly into the alias map, exactly like the `polity_canonical.yaml` seed, and never reaches a merge call. The fold decides only that two surfaces are the same string once case/whitespace/punctuation are set aside — never which spelling is canonical, and never anything about identity elsewhere: the inventory, canonical election and every rendered name page keep every surface exactly as the corpus wrote it. Diacritics are out of scope (measured: folding them collides the genuinely distinct `Galilee` / `Galilée`).

**Transliteration variants fold too, because they are a rendering and not a name (issue #642).** A corpus that writes the Ba'th party twelve ways hands the analyst two half-doors and no whole one: `Ba'th Party` carried 43 notes and not one of Vignal's, `Baath Party` carried 25 including his, and an apostrophe stood between the only writer in the corpus who saw the war and the standard work on the party that fought it. Two renderings vary and so two fold. The **marker** — the apostrophe, the modifier half rings `ʿ` and `ʾ` a romanization writes for ayn and hamza, or nothing at all — folds away; the half rings need saying because Unicode files them as letters, so the punctuation rule above walks straight past them (636 occurrences here). And the **vowel length** — a doubled `a` against a single one — folds to one. Only `a`: measured over the live inventory, collapsing every doubled vowel instead folds `World War I` into `World War II`, `Volume I` into `Volume II` and `EC` into `EEC`, because `ii` and `ee` carry Roman numerals and acronyms where `aa` carries transliterations. This folds the rendering of a name and never its extent: `Ba'th Regional Command` is not `Ba'th Party`, and a fold that collapsed them would be worse than the split it fixes. Diacritics ON a base letter stay out of scope for the reason above; a spacing modifier letter is not one of those — it stands between two letters exactly where an apostrophe stands in the same word's other spelling. Measured over the corpus of record (`sim-2026-07-30`): 49,674 name pages become 49,558, the party's own door becomes 126 notes across 11 sources, and three pairs fold that should not — `Shanxi`/`Shaanxi`, `Ma'an`/`Man`, `JAMA`/`jama'a`, five notes between them, every one of them a page too small to be a door.

### 7.17 Name pages and the link layer

Materialize (§5 stage 8) writes the vault with **no model call** (D11). Four outputs.

- **Prose notes** — `data/vault/prose/`, one per note, frontmatter per §7.2 and Appendix H, body is the note's own text verbatim. Filenames follow the existing budget rule (P0-8).
- **Artifact notes** — `data/vault/artifacts/`, unchanged except that `cited_by` is gone (§7.2).
- **Name pages** — `data/vault/names/`, one per surviving canonical name. Each carries, in frontmatter: `name`, `kind`, `aliases`, `member_count`. In the body: the aliases, then the member notes **as Obsidian links**, one per line, each with its author, year and one-sentence claim so the page is readable without opening anything. Gather appends its section later (§7.18).
- **The note store** — `data/vault/notes.db`, the same notes and the relations the interrogation typed, as tables. Below.

**Why the links live here.** Obsidian treats a link as a connection in both directions, so a name page linking its members draws exactly the same graph as members linking the name — and the whole link layer becomes regenerable. A changed alias map rewrites a few hundred name pages instead of six thousand notes. Notes carry their names as plain strings and never as links (§7.2).

**Deleting an orphaned name page is the existing mechanism, and issue #508 is the largest thing it has ever had to do.** A page whose canonical no longer appears in the index is unlinked on the next run, so a tightened merge never leaves the vault accumulating orphans. The cut set removes 12,309 pages at once on the live layer, taking the index from 62,704 to 50,395, and that arrives through the same path with no special case. §7.16's guarantee that a prose note stays byte-unchanged is unaffected: only name pages move.

**The name-page index (`data/vault/names.jsonl`, issue #634).** A retrieval reader that needs a fact about every name page — how many notes a page carries, how many distinct sources it spans — used to open and read each of 49,674 files itself, measured at 9m22s serial wall clock on the live vault. Materialize already knows every number a reader could want as it writes the pages, so it writes them once more, next to `names/` rather than inside it (a stray file inside `names/` would be read as a page by anything that globs there): one JSONL row per surviving name, carrying `name` (the page's own `name` frontmatter, still the sole authoritative id — never the filename), `filename` (so a reader opens the page directly, no glob), `kind`, `member_count`, and `source_count` — the number of distinct `source_id` values among that page's member notes, a fact the frontmatter alone does not carry and the reason this is a writer change rather than a reader one. **The index is derived and rebuildable, never a second source of truth**: a reader that finds it missing rebuilds it by scanning `names/` itself (threaded — the cost is per-file-open latency, measured at ~40s for all 49,674 pages against the 9m22s serial scan) and writes it back so the next run reads it in one pass; a vault directory that is not writable degrades to the in-memory result rather than raising. Materialize itself always rewrites the whole index on every run, the same way it always rewrites prose and artifact notes.

**The note store (`data/vault/notes.db`, DEC-62, issue #648).** The name pages keep only the node labels: they group notes by the names they share and drop everything else the interrogation typed. Measured (`data/logs/2026-08-04-relational-join-ceiling/`), 4.7% of the corpus's 10,897 `arguing_against` targets joined to anything queryable that way. So Materialize also writes the same notes and their relations as a stdlib-SQLite database, next to `names/`: `notes` (chunk_id, source_id, section, **chapter** — the section's own TOC parent from `chapter_for_section`, the same call the note page makes, `NULL` on the 38.4% of notes whose section the TOC does not place, rather than falling back to `section` — claim, stated position), `note_names` (note → canonical, with the kind THIS note's own answer gave it), `note_arguing_against` (note → the free-text target → the canonical it resolves to, or one row with `NULL` when it resolves to nothing, which is the honest majority), `note_opposed_position` (note → target → argument-map position id, issue #651, below), `note_citations` (note → cited surface, stance, about), `names` (one row per surviving canonical with its kind and its folded form), and `sources` (author, title, date, and **publication year as a first-class integer column**, parsed from the source id's own author-year shape). It is written **atomically** — built beside the live file and renamed over it in one filesystem rename — for the same reason the name-page index is: a Materialize run and a live `axial ask` can overlap.

**The store is derived, never a second source of truth.** `note_names` is exactly the name-page membership (the same union of a node's canonical and alias surfaces over the inventory), so a query over the store and the name page for the same name can never disagree about who its members are — verified on the live vault, where `find_names` and `get_name` answered from the store are byte-identical to the same calls answered from the pages. The one relation the pages never carried is the resolved end of `arguing_against`: a target resolves to a canonical when one of that canonical's own surface forms, **of two or more tokens**, appears inside the target text as a whole-word phrase under the same fold (§7.16, issue #642) every other name comparison uses. Two tokens is measured, not a knob: admitting single-token surfaces lifts the apparent join rate from 44% to 93% and is almost entirely noise from the corpus's own one-word canonicals ("the notion of Free French rule" resolving to `Rule`, "many of his contemporaries" to `His`). At two tokens, 44.0% of targets reach at least one other note and 43,091 cross-source opposition pairs across 339 named scholars and works become queryable — none of which the flat layer surfaced. The remaining 56% are prose descriptions of a position with no distinctive noun phrase to key a join on, needing semantic matching instead of a relational join.

**`note_opposed_position` (issue #651) is that semantic match, folded in as a separate table rather than a second value in `note_arguing_against`.** `axial.argmap.residue` matches each of those remaining targets against the argument map's own positions (§7.16) with one model call, both a section-title-blocked arm and an unblocked arm, keeping the union of whatever either matches — measured to resolve mostly *different* targets, not overlapping ones, so neither arm alone is a safe substitute for the other. A target can therefore carry more than one row here, one per position either arm reached, which is why this is a table and not a column: `mode` (`blocked`/`unblocked`/`both`) says which arm is behind a given row, and `self_referential` flags a row whose target and matched position were drawn from the same source — a real match, but not the cross-source opposition this exists to surface, kept countable rather than dropped. The pass itself only decides and logs; Materialize is what folds the log into this table, the same split every other derived table in this store keeps.

**The name pages are unchanged.** They remain the rendered Obsidian view — this adds a queryable substrate under them, it does not move the wiki. Gather still appends its finding to the page (§7.18), after Materialize has already written the store, so the page stays the one place that finding lives.

**First look.** This stage is the first point at which the founder can open the graph view and see the corpus. Everything before it is invisible on disk. It is sequenced early for that reason, and building Gather before that look happens is a mistake worth naming here.

### 7.18 Gather: the disagreement pass, and pairwise support

**Gather (§5 stage 9, D12) cannot blow the context window, by construction.** The model never fetches, and the packet is assembled by code.

- **The packet.** Per member note: author, year, the one-sentence `claim`, `position_of`, `arguing_against`, then `position` where the note has one — roughly 800 characters. Nothing else. Gather never reads a note's full text.
- **`position` is rendered only when the note's own record carries the key (issue #496).** The corpus is a mixed frame (§7.15) and stays one: `build_packets` reads the field on key presence alone, never on truthiness or `frame_version`, so a pre-0.2 record with no `position` key produces a packet with none.
- **The bracket is reserved first, and `claim` is truncated into whatever is left (issue #500, D1, fix 2026-07-30).** The per-member cap used to truncate the whole rendered line's tail, so whichever field was rendered last lost the most. Measured over the live corpus (6,148 notes carrying an interrogation answer), that cost **22.4% of all rendered packets `arguing_against` entirely** — the one clause §7.15's own measurement found separates contested names from uncontested ones (1.9x–2.4x lift), which Phase B's contestedness derivation reads. `claim` is the field that actually runs long (median 245 characters of a 483-character untruncated packet), so the bracket (`position_of`; `arguing_against`; `position`, where present) is rendered in full first, and `claim` alone is truncated into the cap's remainder — every bracket field now survives whenever the packet fits under the cap at all, and the loss moves to `claim`. This is a single arithmetic split, not a second constant: no field carries its own budget, only `claim`'s share is computed as what the fixed parts leave behind. The one degenerate case — a bracket long enough that, combined with author/year, it alone meets or exceeds the cap — falls back to the pre-D1 whole-line-then-tail truncation. This deliberately breaks the pre-0.2 byte-for-byte render guarantee this section used to state for any packet that hits the cap, old format or new — the disagreement record's key is a sha256 over the name's rendered packets (below), so this re-keys every name whose packets were ever truncated, which #500's corpus pass pays for once, alongside #498's re-key.
- **The cap shipped at 400 first and moved to 800 the same day, because the bracket is not short and bounded by construction (correction, 2026-07-30).** Measured over the whole corpus, the bracket alone runs a median 221 characters, p90 387, max 978 — close enough to a 400 cap that reserving it still left 11.5% of notes (707) with no remainder for `claim` at all, the degenerate case above. At 400 the fix only took `arguing_against`'s loss rate from 26.8% to 8.3%, not to zero. 800 clears the measured p90 with room: the degenerate share drops to 0.1% (5 notes), and `arguing_against` is lost nowhere outside it. The mechanism did not change, only the number.
- **A metadata-gap sentinel never stands in for an author (fix, 2026-07-29).** `axial.vault.bibliographic_value` deliberately renders the `unavailable`/`not_attempted` sentinels (§7.13) as themselves in a note's own frontmatter, so a gap stays visible rather than reading like a blank answer — that behaviour is unchanged. A Gather packet is not frontmatter, and handing the model a sentinel string as if it were a person produced exactly that: two of a 100-name stratified sample (`data/logs/2026-07-29-gather-stratified-sample/`) named an author as "the 'unavailable (2000)' author". Gather now falls back to a name derived from `source_id`'s own `<author>-<year>-<hash>` shape (`axial.envelope.compute_source_id`) when the source-metadata record's `author` field is a sentinel — real and legible (`heydemann-2000-66701ffbb36c` → `Heydemann`) rather than invented, since no note reaches Gather without a source_id. The underlying metadata gap was not fixed by this, and was closed separately as a `data/` operation (#473): `heydemann-2000-66701ffbb36c.json` now carries the values printed on its own title page, which the damaged scan's watermark had cost it. The fallback stays, because the sentinel it guards against is a general state, not one book's.
- **The budget is a constant in code, not an instruction in the prompt.** A prompt-side budget is a request; a code-side budget is a guarantee. The constant is stated in the module and inspectable. It is **two** constants, not one: a per-member cap (the "roughly 800 characters" above) and the whole-block budget. The per-member cap is what makes the block budget arithmetic rather than an average — without it a single pathological answer could exceed the block budget on its own, and the guarantee is stated over *any* name at *any* corpus size.
- **Batching is a designed path, not an edge case.** A name whose packet would exceed the budget is split into batches; Gather runs per batch; a short final call merges the batch findings into one. Large names are the interesting ones, so this path runs often and is built first-class. The merge call carries the batch findings and no packets at all, so its own size is bounded by the batch count rather than by the size of the name. The merge synthesizes **partial evidence about one name**, never adjudicates between the batch findings as if they were competing claims — an earlier wording that told the model to do exactly that broke the merge on the corpus's biggest names (below).
- **A name fewer than two member notes reach is not asked about.** A disagreement needs two parties; one note has no second author to disagree with. Definitional, not a threshold, and it is what keeps the pass's call count proportional to the names that can carry a disagreement rather than to the whole index.
- **A name below a configured minimum member count is not asked about either — a founder scope decision, not a definitional gate (2026-07-29).** Gather now asks only about names at least `gather.min_members` member notes reach (`config/pipeline.yaml`, defaults to **10**), skipped before a packet is assembled or a model call made, the same as the gates above and around it, and counted separately in the run summary (`names_skipped_below_min_members`). Measured on a seeded 100-name stratified sample (`data/logs/2026-07-29-gather-stratified-sample/`), the value of asking concentrates almost entirely in large names — 65% of the largest 20 names produced a real disagreement, ~22% of the upper decile (10–41 members), only 5–13% of a uniform-random name (median 3 members) — and on the live index (20,321 eligible names, 118,963 member slots), cutting at 10 members drops 90% of the pages and keeps 52% of the member evidence: the value concentrates where the volume does not. This is distinct from the two-member gate above, which is definitional and never moves; this cut is a movable product-scope choice, exposed in config so it can be tuned against measurement without touching `src/`.
- **Gather no longer gates residue of its own, because none reaches it (issue #508).** A bare page number, a plain century and an apparatus pointer each used to be skipped here, before the packet was assembled. §7.16's cut set removes all three at inventory time, so no such canonical exists in the alias map Gather reads, and a second gate could only ever report zero. The 2,010 pages that lose members to the cut re-key their disagreement record and are re-asked; every page whose membership is unchanged reuses the decision it already has.
- **A finding can say "no disagreement" without prose.** The response's `disagreement` field is **nullable**: `null` means the authors gathered here were read and genuinely do not disagree, distinct from a shape failure (a missing key or an empty string), which is still re-asked. This is what lets the pass tell "nothing found" apart from "found something" structurally instead of by classifying the finding's prose — a regex undercounted the same judgment twice on wordings that share no vocabulary (e.g. "do not present any disagreement" vs. "they address different aspects").
- **Null findings are dropped before the merge step.** A batch's null finding carries no evidence for the merge call to read. If every batch of a name comes back null, the name itself is null and **no merge call is made at all** — a real saving on the long tail, not just a correctness fix. If exactly one batch finds something, that finding **is** the name's disagreement; it is not merged against nothing.
- **A merge call handed real evidence never returns null.** By construction the merge step is only ever called with two or more surviving, non-null batch findings, so a null merge result is never an honest reading — there is no way for two genuine disagreements to combine to nothing. This is enforced as a code invariant, not asked for in the prompt: a null merge response is treated as a content-shaped failure and re-asked within `complete_json`'s own bounded budget, and if the model still insists on null once that budget is exhausted, code — not another model call — falls back to the surviving findings' own text, joined, so the pass never silently discards evidence it already paid for. The all-batches-null path above is the **only** way a name's disagreement is still null after batching (#472 shipped this bullet's null-dropping half but regressed both the batch prompt, which took null as its cheapest answer, and this merge guarantee — measured on the same 100-name sample, `data/logs/2026-07-29-gather-rerun-after-472/summary.md`; fixed here).
- **The output**, when there is one, is what the authors gathered at this name actually disagree about, written onto the name page under its own heading, plus **name-to-name links** where the disagreement runs between two names the index already carries. The model names what it referred to; code keeps only the names the index actually carries, because a link to a page that does not exist is not a link. **A null finding writes no section at all** — not an empty heading, and only when it is the write's own selection: a canonical name can carry more than one record over time (an upstream re-render changes a name's packet hash without changing the canonical, #495), so the write picks the **newest non-null record for that canonical**, falling back to the newest record only once every one of them is null. Under D4 a Gather finding is a retrieval hint, never a citation — a wrong hint costs one wasted hop, a missing one costs synthesis that never happens — so at a measured 53% flip rate between two reads of the same name, recall is the side to err on: a later null re-ask can no longer take a real finding off the page.
- **Every disagreement is also written as a record** (`data/names/disagreements.jsonl`), one per name, in the convention the per-note answer records set (§6): the name, the member-note ids that fed it, which batch produced each finding, whether the page's text survived a merge call or came straight from one under-budget call, and the text itself (`null` when the finding is null). It is the pass's answer artifact and its resume checkpoint at once, keyed by a content hash of the name's own rendered packets — so an interrupted run resumes, a re-run over unchanged packets makes no model call, and a changed upstream re-asks exactly the names whose packets moved. **A null finding is recorded exactly like any other** — the checkpoint is what stops a re-run re-asking and re-spending; only the page write is skipped. It exists because §10's replacement quality measure is still undecided: every candidate instrument needs this provenance, and writing it during the pass is what stops a later eval having to re-run the corpus to recover it.

- **Gather reports the same four `units_*` counters, read straight off `disagreements.jsonl` itself, with no separate manifest (issue #677, #678).** `units_total` is the name count in scope, past both member-count gates; `units_reused` is how many of those already carried a disagreement record before this run's worker pool spent a single call; `units_asked` is the rest; and `units_asked_touching_new` narrows that to names whose own member `chunk_ids` touch a source absent from EVERY disagreement record already on disk at the start of this run. No new artifact is needed for that last check: a disagreement record already carries the `chunk_ids` it was written from (§6), so the prior run's own source coverage is exactly the union of those fields over every record `load_disagreements` reads back before this run's first call — the same "ledger state right before a call is spent" rule the merge and map passes' own counters use. Absent any recorded disagreement (a first-ever run), every asked name counts as touching new. Running the pass twice with no corpus change reports `units_asked: 0`.

**Re-running Materialize clears the disagreement sections, and re-running Gather restores them for free.** Materialize (§7.17) rewrites a name page whose content differs from what it would write, which includes the section Gather appended. That is not a conflict to design around: Gather's records are on disk, so the restoring run makes no model call.

**Pairwise verbatim support (§5 stage 10, D13)** is a separate, narrow step, built only if Gather's output shows it is needed. It reads exactly **two** notes in full — about 18k characters at the `[3500, 9000]` band, safe by construction — and returns the quoted grounds for one disagreement. Keeping it separate is what lets Gather stay cheap: one pass reads many notes shallowly, the other reads two notes deeply, and neither has to compromise for the other.

### Must-Have (P0)

New criteria are **appended with new numbers**; existing numbers are never reused or renumbered, so a struck criterion stays visibly struck at its old number. Reading order is therefore not pipeline order: Reconcile (P0-12) and Gather (P0-13) run before and after Materialize (P0-8) respectively.

**P0-1 Intake validation.**
- [ ] Accepts `.pdf` and `.docx`; rejects everything else with a logged reason.
- [ ] Detects absence of a text layer and rejects the file with a clear message.
- [ ] Given a scanned PDF, when intake runs, then the file is rejected and never silently passed downstream.
- [ ] **Rejects a source filename stem too long to ever produce a writable note filename.** `axial.envelope.compute_source_id` folds `path.stem` into every id derived from a source, and `chunk_id` (`<source_id>_<order_key>_<slug>_<NNN>`, §7.7) folds `source_id` into a vault note filename; a source pulled from libgen/Z-Library routinely carries a stem long enough that the resulting filename cannot exist under Windows' MAX_PATH at any directory depth. The safe stem length is **derived**, not hand-picked, from the constants already governing that budget elsewhere (`_WINDOWS_MAX_PATH`/`_PATH_SAFETY_MARGIN`, `_SLUG_MAX_LEN`, the fixed-width hash/order-key/index pieces of `chunk_id`'s own grammar) and from the real, live-measured depth of the directories a `chunk_id` is written under — so it adapts to wherever the repo is actually checked out rather than assuming one. Rejected in the same early gate as the extension check, before any extraction, model call, or metadata write; the error names the file, its stem length, and the derived limit, and tells the operator to rename it shorter. This closes, at the source, the defect independently patched downstream four times (PR #377's lost vault notes, #394's unreachable notes, #395/#396's sampling defects).

**P0-1b Holdings-completeness check (model-adjudicated, flag-only).**
- [ ] A check runs at intake on every accepted source and detects a **partial holding** — one volume of a set, a truncated scan, an extract circulated as the whole work (§7.11). It reads the raw text layer intake already builds (P0-1) and reads **neither the structural tree nor the envelope**. Observable: no tree or envelope file is read, and none needs to exist, for the check to run.
- [ ] **It runs in the pipeline, once per source.** A source ingested through the real path is judged and the judgment persisted (§7.12); a later pass over the same source makes **no** model call and reads the record instead. Observable: two consecutive passes over the same corpus make one holdings call per source in total, not two (#303).
- [ ] **Deterministic pre-processing runs first.** The physical page count is read from the file, and **running headers and footers are stripped** from the text before any of it is read for judgment. Observable: on the `tilly` source, whose contents heading extracts as `viii Contents`, the cleaned window handed to the model carries the heading without the folio. The **opening pages are shown a second time as printed**, unstripped, for the bibliographic read (§7.13, #316); the cleaned windows the holdings judgment reads are unchanged by that.
- [ ] **The judgment is one model call over the cleaned text** — the front matter plus whatever tail material the judgment needs — deciding together: the **document kind** (book / research paper / chapter offprint / fragment), the **extent the document claims** for itself where it states one, and **whether the file covers that extent** given the physical page count. It is one judgment, not separately-scored signals.
- [ ] **A research paper with no contents page is complete and is not flagged.** Observable: a complete research paper carrying no contents page passes with no flag.
- [ ] **Corpus-level accuracy — the bar, and it does not move.** The check flags exactly the two known partial holdings and nothing else: **2 true positives, 0 false positives, 0 false negatives** (#267, #268). The two halves are gated differently (§7.11): the **false-positive half is re-measured on every change**, over the 30 real sources in `data/sources/` — 0 flags; the **true-positive half is re-measured when the check's judgment changes** — its questions, rules, model or windows — and rests on #284's measurement otherwise. **No live positive control exists** (§7.11); the flag-raising tests feed a recorded response and pin plumbing, not judgment.
- [ ] **The flag records its measurement**, never a bare boolean. It carries at least: the source; the **document kind** concluded; the **claimed extent** where the document states one, with what stated it; the **observed extent** (physical page count); and the **model's stated reason**. A source judged complete produces **no flag**.
- [ ] **Flag-only, never a reject.** The check never rejects a source, never halts intake, never repairs or re-fetches, and never alters what any later stage sees. Observable: given a flagged source, intake still succeeds and the source proceeds through extraction, envelope, chunking, interrogation, and vault write exactly as an unflagged source does.
- [ ] **DOCX.** The check runs on DOCX, which exposes no physical page count. It may flag a DOCX whose front matter names it a part of a larger work; it must **not** flag a DOCX merely for lacking coverage evidence, which is unobtainable rather than damning (§7.11).
- [ ] **Any tunable is stated and small in number** — the front-matter window, the tail window, the as-printed opening-pages window, and the running-furniture recurrence floor — with values **set by measurement over the 30 sources** and not asserted in the spec (§7.11). **No safe-direction-degradation guarantee is claimed**: the earlier one was measurably false (#282).

**P0-1c Persisted source-metadata record.**
- [ ] Intake writes one JSON file per source at **`data/source_meta/<source_id>.json`**, keyed by the same deterministic `source_id` used for the tree, envelope, and chunk artifact (§7.12). It is written before extraction.
- [ ] It carries at least: the **physical page count** where the format exposes one; the **holdings flag** from §7.11 in full, or an explicit no-flag for a source judged complete; **whether that judgment has been made at all**, distinct from a no-flag; the **full sha256 file hash**; the **author, title, date and publisher** read at intake (P0-1d); and the raw **identifier** found in the front matter, kept for audit even when it did not resolve or was rejected by the identity guard.
- [ ] **It survives envelope regeneration.** Observable: regenerating a source's envelope leaves its source-metadata record byte-unchanged.
- [ ] **Boundary rule.** The record holds facts about the **artifact** — obtained without interpreting the argument, and unchanged when a model is re-run against the same bytes. The envelope holds what the model concludes about the **work** (§7.12).
- [ ] **No source text.** Per DEC-23 the record carries no source text and no verbatim excerpts; values and short reasons only.
- [ ] The holdings flag **reaches a downstream reader** through this record. Observable: a flagged source's flag is readable after intake without re-running the check.

**P0-1d Author, title, date and publisher read at intake.**
- [ ] `author`, `title` and `date` are read at intake **from the PDF itself** — its embedded document metadata and its title page — and recorded in the source-metadata record (§7.13). The envelope LLM pass does not produce them.
- [ ] **The filename is never a source** for any of the four. Observable: a source whose filename slug differs from its printed title yields the printed title, or `unavailable` — never the slug.
- [ ] **Three distinguishable states per field**, readable off the record: a **value with recorded provenance** (embedded metadata, title page, or an identifier lookup); **unavailable** (read attempted, nothing recoverable); or **not attempted**.
- [ ] **The recorded title is the whole title.** A title page printing a main title and a subtitle on separate lines yields both, joined as printed. Observable: the model is shown the opening pages as printed, so a main title that also runs as the book's header survives the running-furniture strip (§7.11, §7.13, #316).
- [ ] **No value is invented to avoid `unavailable`.** Junk embedded metadata is recorded as unavailable, not passed through.
- [ ] **An identifier-based fast path (issue #326), gap-fill only.** A checksum-valid ISBN or syntactically valid DOI captured from the front matter (no network) is resolved against Open Library/Crossref, cached to disk by identifier, and **fills** `title`/`author`/`date` only when the field is currently `unavailable` — the catalog never overwrites the file's own read. `publisher` has no other reading mechanism, so it fills whenever a fetch resolves and the guard passes. Two safeguards gate a fill: a multi-candidate capture resolves and compares **every** candidate, filling only when they plausibly agree on both author and title; and the fetched author must plausibly overlap intake's already-known author. The raw identifier is recorded regardless.
- [ ] **One answer downstream.** The source-metadata record is the sole origin of these four fields; the envelope no longer carries `author`/`title`/`date` (§7.3). The vault's `source_meta` block keeps its five keys, composed from the record for the first three and the envelope for the last two. A source with **no record at all** fails the vault write loudly, with a typed error naming the missing record.
- [ ] These fields are threaded into every interrogation call as source context (§7.15, P0-6).

**P0-2 Structural extraction with fallback.**
- [ ] docling produces a hierarchical tree separating prose from non-text artifacts.
- [ ] On docling failure/degenerate output for a source, Unstructured runs as fallback for that source; the fallback is logged.
- [ ] The structural tree is written once per source (keyed by `source_id`) and read by later stages (not re-extracted); a source is re-extracted only when no persisted tree exists for its `source_id`. Observable under D16: a full corpus re-run below extraction re-extracts zero books.

**P0-2b Post-extract text normalization.**
- [ ] At tree-build time (stage 2), a deterministic, model-free normalization pass cleans each block's `text` before the tree is persisted. It alters no block's `label`, `type`, or `order` and does not change the tree's shape (§7.4).
- [ ] Normalization is organized as independent transforms, each a no-op when its target defect is absent: a clean-font source passes through materially unchanged.
- [ ] Whitespace (universal): soft-hyphens (U+00AD) are stripped, runs of whitespace collapse to a single space, and space-before-punctuation is removed.
- [ ] Glyph repair (font-specific, no-op when absent): detached combining marks (Unicode category Sk) are dropped or reattached; recoverable Private-Use-Area offset glyphs are decoded (e.g. `chr(c − 0xF700)`) and unrecoverable ones dropped; a curated allowlist maps known glyph-name leaks (`asper`→`ʿ`, `lenis`→`ʾ`, `H####`/`Q##` font codes → drop); dotless-i is normalized.
- [ ] Glyph-name repair is a curated allowlist, never a blanket `/word` strip: legitimate slash-words (`and/or`, `threat/opportunity`, `/reliefweb`, `/p111`) are preserved.
- [ ] Out of scope and left untouched: middle-dots (`·`), correctly-composed accents, and mathematical symbols.
- [ ] Small-caps letter-spacing repair is **not** performed by the pass — descoped (§7.4).

**P0-3 Structural-envelope pass.**
- [ ] One envelope JSON per source containing thesis, TOC, scope, stated argument.
- [ ] The envelope is written once and **read by the interrogation pass** (not recomputed): its thesis, scope and stated argument are the book-level context in every per-note call, and its `toc` supplies the note's chapter (§7.15).
- [ ] The envelope's locked shape is `{source_id, thesis, toc[], scope, stated_argument}`: `thesis` / `scope` / `stated_argument` are non-empty strings, `toc` a **non-empty list of `{title, children[]}` objects**, no field nullable, and no new field. `author`, `title` and `date` are **not envelope fields** (§7.12, §7.13, P0-1d).
- [ ] The pass never sends the model an empty or near-empty evidence block. When the intro / abstract / conclusion heading heuristic selects little or no text, input selection **widens to a substantive head-of-tree slice** whose size is a stated tunable proven via inspection (§7.3). Observable: given a tree whose top-level headings match none of intro / abstract / conclusion, the assembled envelope evidence still carries substantive source text.
- [ ] Envelope evidence for a matched section is the **full text of the selected sections** — the section's own prose plus its children's (§7.3).
- [ ] A matched intro / abstract / conclusion section whose descendants are **overwhelmingly single-citation / bibliographic leaves** is detected by an **aggregate citation signal across the section's descendants** and **excluded from the matched-section evidence before the evidence-floor check** (§7.3, #222). The aggregate share is a stated tunable proven via inspection, and the detector is conservative. Observable: given the real Tilly tree, the assembled evidence excludes that section and carries substantive body prose; given a normally-sectioned born-digital source, the evidence is unchanged.
- [ ] The head-of-tree widening slice proceeds in tree order but **skips a leading front-matter / apparatus prefix** and begins at the first genuinely substantive body prose; the skip is a stated tunable, bounded so it can never consume the whole source (§7.3, #222).
- [ ] The `toc` is a **reconstructed nested `{title, children[]}` hierarchy** grounded only in **two signals** read from the cached tree, reconstructed within the same single envelope call (§7.3, #235), excluding subsection noise, OCR-garble, mislabelled body lines, and apparatus. It stays a **non-empty list**, with a deterministic fallback to the tree's detected heading list on reconstruction failure. Observable: given the real Tilly tree, the reconstructed `toc` is a compact clean chapter hierarchy, not the ~165-entry flattened heading dump.
- [ ] The extraction is **grounded by construction**: the prompt instructs the model to base `thesis` / `scope` / `stated_argument` only on the supplied source text, and not to infer from the title, filename, or outside knowledge (§7.3).
- [ ] Model reasoning is **ON** for this pass (per-pass configurable, §7.9), carried in `config/pipeline.yaml`, never hardcoded.

**P0-4 Chunking (recursive/structural, deterministic, LLM-independent).**
- [ ] Chunk boundaries are found by a **recursive/structural splitter** (#165, #191) — the sole chunk mechanism — that splits along the prose's separator hierarchy (paragraph → line → sentence → character), descending to the finer separator only when a piece still exceeds the band. The chunk critical path is deterministic and model-free: **zero embedding-model calls and no text-generating LLM call**.
- [ ] **The band is `[CHUNK_MIN, CHUNK_MAX]` = `[3500, 9000]` characters (D1).** Every emitted note falls within it, enforced by a deterministic guard pass wrapped around the splitter's detected breakpoints — an observable property, since sizes are measurable off the on-disk artifact (§7.7). MAX side: any chunk above `CHUNK_MAX` is recursively split at its next-best internal boundary, so a section larger than `CHUNK_MAX` (today up to ~143k chars) is split into multiple in-band notes, never emitted whole and never skipped for size. MIN side: a chunk below `CHUNK_MIN` is **merged into a same-section neighbour — never dropped and never merged across a section boundary**: into its same-section **predecessor** when one exists and the result would not exceed `CHUNK_MAX`, otherwise **forward** into its same-section successor.
- [ ] **No note spans two chapters (D2).** Chunks are built inside a single section node and merging is same-section only, so no note can cross a heading. Observable off the artifact: every record's `text` comes from exactly one `section_order`.
- [ ] **A section shorter than `CHUNK_MIN` yields one below-floor note, and that is accepted (D3).** A sub-floor chunk that is its section's sole chunk, with no same-section neighbour to absorb it, is **kept** as-is. Observable: `axial chunk examine` reports the count of such notes, so the trade-off is visible rather than assumed.
- [ ] The chunk stage consumes a **prose-only routed tree** (§7.8): apparatus and artifact blocks are removed upstream by the source router and never enter the chunk path.
- [ ] Type-detectable non-prose is dropped by the router on structural `label`, not by the chunk stage; the residual high-non-alphabetic-ratio rule survives only as a backstop. A legitimate long section is split, not skipped, and every drop is recorded with a reason in the router-owned skip record (§7.8).
- [ ] The source router also drops **content-detected apparatus** (§7.8), two-stage: a cheap deterministic pre-filter flags candidates, and **only flagged candidates** are sent to a single bounded per-block classification call. Clean prose reaches the chunk stage with **zero** model spend. The arm is conservative and never overrides the never-drop-on-uncertainty rule. Reasoning is ON for this classification call (§7.9).
- [ ] A **post-split fragment floor** (#193, #197) drops an emitted candidate chunk, before it reaches the on-disk artifact, only when it is unambiguous non-content boilerplate: a **blank-page notice**, or a **low-alpha fragment** (alphabetic ratio below **0.45**, a tunable proven via `axial chunk examine`). Measured off the artifact: no emitted note is a blank-page notice or has an alphabetic ratio below 0.45. Length alone never triggers the drop; each drop is recorded with its own distinct reason in the router-owned skip record.
- [ ] Output notes carry stable `chunk_id`s and preserve section provenance (verbatim section heading + section order).
- [ ] Chunk records are written to the on-disk artifact (§7.7) before any downstream LLM call, and are inspectable without LLM spend.
- [ ] The chunk stage reads the persisted structural tree only (it consumes no envelope) and makes no generative LLM call.
- [ ] **The band change re-cuts the corpus (D16).** Re-chunking off the cached trees renumbers every `chunk_id`; the distribution is reported (below-floor count, short-whole-section count, notes per book) and **figure/table records are confirmed to survive off the cached structure rather than needing to be re-paid** (§7.7).

**P0-4b Chunk examine (inspection without LLM spend).**
- [ ] `axial chunk examine` reports note-quality stats from the on-disk artifact — total/per-source counts, size distribution (verifying the two-sided band), boundary sanity (notes above `CHUNK_MAX`, notes below `CHUNK_MIN`, sections split), and the count of sub-floor chunks merged into a same-section neighbour — making zero LLM and zero embedding-model calls.
- [ ] Its skipped/dropped-block report reads the **router's** decisions from the router-owned skip record (§7.8) — the single source of skip truth — not a per-pass guard.
- [ ] Downstream interrogate, artifact, and materialize stages consume the on-disk chunk artifact (§7.7).

- [ ] The pass makes **no LLM call** (issue #429; struck from this list: "each non-text artifact receives exactly one `artifact_role` from the taxonomy" — Appendix D is retired, see its own note).
- [ ] Artifacts are written to the artifact pool, not embedded in prose notes.

**P0-6 Interrogation (D6, D7, D8, D14).** *Replaces P0-6 Schema-driven tagging, struck with the tag pass (D4).*
- [ ] **One call per note.** Every note in `data/chunks/<source_id>.jsonl` is read exactly once and produces exactly one answer record in `data/answers/<source_id>.jsonl`, keyed by `chunk_id` (§7.15). One draw; no voting layer.
- [ ] **The context is exactly §7.15's list**: the note text, its author/title/date from the source-metadata record, its book's thesis/scope/stated argument from the envelope, its chapter from the envelope's `toc`, its verbatim section heading, and the domain frame's examples. Observable: the assembled prompt for a note carries its book's thesis, and carries no text from any other source.
- [ ] **No web and no external lookup** (charter Principle I). The prompt instructs the model to answer only from the supplied passage and context, and not from what it may know about the book. Observable: the pass makes no network call other than the model call itself.
- [ ] **All thirteen questions of §7.15 are answered**, including `citations` with its `support` / `foil` / `authority` stance and `names` with a `kind` per name. A figure or table the prose names is harvested as a name (`kind: figure` / `kind: table`) — this is the replacement for the deleted cross-reference pass (D5).
- [ ] **Abstention is explicit (D7).** A field the passage does not support records `not-in-passage`, optionally with a one-clause reason, including the "cannot judge between X and Y" case. Observable: a note whose passage states no mechanism records `not-in-passage` for `mechanism`, never a plausible-sounding one. A field that is absent means the call failed, and is recorded as a failure, not as an answer.
- [ ] **The free answer comes first and the nearest example is separate and marked (D8).** The prompt asks each question in the model's own words before presenting that question's examples; the record carries `<field>` (free text) and `<field>_nearest` = `{example, fit}`; **code never normalizes, rewrites, or bridges the two**. Observable: an answer that matches no example is recorded verbatim with `_nearest.fit: none`, and nothing quarantines.
- [ ] **The collapse check runs and is reported.** The share of free answers string-equal to one of that question's example values (casefolded, whitespace-collapsed) is measured over the sample and over the full run and printed with the run summary. A field whose free answers are overwhelmingly verbatim example strings is a stop-and-fix: the pass has rebuilt tagging (§7.15).
- [ ] **The pass runs on `z-ai/glm-5.2` (D14)** via `model_by_pass`, under a pass name that is **not** `"interrogate"` — that constant belongs to Phase B's brief pre-pass (`src/axial/llm.py:303`). This document specifies `note_interrogate` (§7.9). Reasoning is OFF by default for this pass.
- [ ] **A ~50-output sample gate opens the run (D14).** The pass stops after roughly 50 notes and reports: the outputs themselves, the collapse-check numbers, the abstention rate per field, and the cost probe below. The remaining calls run only after the operator has read the sample. This is the guard against the family's known variance (DEC-27/28) costing 6,000 calls instead of 50. The gate is **operated**, not hardcoded: the pass takes an explicit note limit, and a run that stopped at one reports itself incomplete, so a truncated run is never mistaken for a finished source. Resuming is free — the artifact is the resume point, and the notes already answered are not paid for twice.
- [ ] **A cost probe is reported**, measured not estimated: tokens in/out and cost per note from the sample, extrapolated to the corpus, in the run summary.
- [ ] **Per-note fault isolation and reconciliation.** A single note's failure is recorded against its `chunk_id` with a reason and skipped; the source continues. A source where every note fails raises loudly. At end of source, answered + failed + skipped must equal the chunk artifact's count for that source, or the pass raises rather than returning a silently short result (§7.15).
- [ ] **No vocabulary gate anywhere in the pass** (D9): no membership check, no correction re-ask, no `out_of_vocab` quarantine.

## 10. Success metrics & eval

> **STRUCK (D15).** Per-axis agreement against hand labels is retired with the layer it measured.

**D15's deferral is retired (DEC-54, issue #447 → #478).** Reconcile's index and Gather's output both now exist, which is what the deferral below was waiting on. **The unit is the Gather disagreement entry** — the only open-text judgment Phase A v1 emits and the only artifact that can be wrong; a name page is a container and the end-to-end answer belongs to Phase B. **The reference is grounding, not taste**: an entry names positions and attributes them to authors, and §7.18's disagreement records already keep the `chunk_ids` behind each one, so "is this real?" decomposes into two checkable questions — is each attributed position actually present in a note that was cited for it (**attribution**), and do the attributed positions actually oppose each other rather than agree (**conflict**). Both are answered from stored provenance, with no Gather re-run.

**The instrument: `axial gather-eval`.** `axial gather-eval sheet` emits a real seeded, stratified sample (~30 entries across the member-count bands `10–20`/`20–50`/`50–100`/`100–300`/`300+`) in the shape §7.5/Appendix I's founder-marking sheet already uses; `axial gather-eval score` judges every scoreable entry (rebuilding the exact packet Gather saw from its own `chunk_ids`, reusing §7.18's own packet code — never re-running Gather), scores the founder's returned marks against the judge's own verdicts once they exist, and re-asks a seeded sample of ~50 null entries at Gather's own settings, bypassing the disagreement checkpoint entirely, to report how often a null flips to a real finding on an identical packet. One record per judgment is appended to `data/names/gather_eval.jsonl`, content-keyed the same way `disagreements.jsonl` itself is — that record doubles as the resume checkpoint. The founder-vs-judge agreement is read before the full run is trusted; the judge and Gather are configured to different model tiers (`gather_eval` vs. `gather` in `config/pipeline.yaml`), the same self-grading guard `CHARTER.md` §2 requires of the attribution and grounding gates elsewhere.

**Not yet set: the ship-blocking bar.** #447 ruled the grounding rate becomes Phase A v1's rung-3 pass/fail gate, with the bar read off what the first real measurement shows rather than guessed in advance — a follow-up once `axial gather-eval score` has run over the live corpus. Until then this is a measurement, not yet a gate.

**Why it was deferred, for the historical record.** Open answers cannot be scored against a closed key, so the replacement is not a swap of one metric for another — it is a new question about what "good" means for this pipeline. The answer depends on output that does not exist yet. Reconcile's index is the first artifact that reveals what is measurable: how many names the corpus actually yields, how many are junk, how sharply merged clusters separate, how many notes a typical name gathers, how often a Gather packet finds a real disagreement. Choosing a metric before seeing that is guessing, and a guessed metric that then gets built into a gate is worse than none.

**Deferring the metric does not license deferring its inputs.** Every candidate instrument — founder adjudication over a sample, a model panel, self-consistency across draws — needs to know where a given disagreement came from. So Gather writes that provenance as it runs (§7.18's disagreement records: the name, the member notes behind it, the batch each finding came from, whether it survived a merge call). Not collecting it would have made the choice of metric cost a re-run of the corpus pass, which is exactly the spend the deferral was meant to protect.

**What the deferral does not license.** Three things stand in the meantime.

1. **The charter's rung-1 obligation is unchanged.** `CHARTER.md` §1.5 requires substrate fidelity to be a checked layer, and §2 makes rung-3 gates ship-blocking in the phase that builds them. Phase A currently has **no rung-1 instrument**. That is a known, stated gap for the duration of this feature, not a repeal. The charter's own cross-references to this section are stale while the gap is open (Open Questions). *(Closed by `axial gather-eval`, above — the gap described here no longer holds.)*
2. **Inspection is not measurement, and is not a substitute for it.** What Phase A v1 has instead, for now, is what a builder can observe without an instrument: the chunk-band distribution off the artifact (P0-4b), the abstention rate per field and the collapse-check numbers off the interrogation run (P0-6), the cluster-size distribution off Reconcile (P0-12), and the graph itself (P0-8). These are how a slice knows it worked. They are not a quality score and must never be reported as one.
3. **The decision has an owner and a trigger.** The replacement measure is chosen once Reconcile's output exists — after slice 05, before any claim about the pipeline's quality is made outside this repo. See `plans/phase-a-v1/README.md` (D15).

**What survives from the old section, because it is about reading numbers rather than about tagging.** Two constraints bind any agreement-shaped figure this project ever reports again, and they were learned expensively (DEC-30):
- **Agreement cannot exceed the annotator's own reliability.** Report intra-annotator (test–retest) reliability alongside any agreement figure, or the figure is uninterpretable.
- **Only compare within one model family.** Same-family agreement runs ~0.25 higher than cross-family on identical instructions, with no design change whatsoever; mixing the two manufactures illusory gains.

Every number this project ever measured on the simulated corpus (DEC-29) is a **provisional development signal, permanently** — real academic input is not coming, so the simulated corpus is the only corpus those figures were ever measured on and no teardown will change that. A simulated number is never promoted.

# Appendices — Syria domain frame

**What these appendices are, in v1.** They are **examples for the interrogation prompt** (D8, D9). They were controlled vocabularies: closed lists a tagger had to pick from, enforced by a validator that quarantined an off-list value. That enforcement is gone, and so is the tagger. What survives is the content, in a different job: it shows the model what a good answer looks like *in this domain*, after the model has answered in its own words.

Three consequences, and they are the whole point of the reframe:

- **An answer that appears in no list below is normal.** It is not an error, it is not corrected, and it is not quarantined. Most answers will not match a list, and a run in which most answers *do* match is a failed run (§7.15, the collapse check).
- **The lists are shown second, never first.** Each question is asked open, in the model's own words, before that question's examples are presented; the nearest example is a separate marked field (§7.15).
- **The status flags are inert.** `[FIRM]`, `[TENTATIVE]`, `[CONTESTED]`, `[CANDIDATE]`, `[PROPOSED-CUT]` denoted a gold-set adjudication process that is retired (D15, D16). They are preserved because `config/domains/syria/schema.yaml` still carries them and because they record the frame author's own confidence, but nothing reads them and nothing acts on them.

**Appendix D is no longer an exception (issue #429).** It was kept as the one closed set on the stated ground that it was "a routing decision over six values made by a different pass, not a description of an argument." Measurement refuted that ground: two independent runs over the same source disagreed on `artifact_role` for 48.5% of artifacts and flipped the keep/discard bit on 13.1% of them, so the six-way decision did not reproduce either. The axis and the artifact pass's classification call are both retired; see Appendix D.

## Appendix C — Empirical-scope examples, and where polities go now

In v1 these are examples for the `ranges_over` and `stops_holding` questions (§7.15). The answer is prose: what the claim ranges over and where the author says it stops holding. That is strictly more than a bucket, and the "where it stops" half has no ancestor in this list at all.

- `scope:general` — theory with no specific empirical case (Mann on autonomy; Brubaker on groupness).
- `scope:comparative` — explicit cross-case comparison (Skocpol on France/Russia/China).
- `scope:regional` — a region without single-country focus (MENA, post-Soviet, post-colonial Africa).
- `scope:country-case` — a specific polity. Most of the Syria literature (Hinnebusch, Akdedian).
- `scope:sub-national` — a city, sub-region, single rebel group, or institution.

**Why the axis existed, and what serves that need now.** The axis existed so a brief like "does Mann's infrastructural power apply to post-2011 Syria" could retrieve the general statement and the country case *separately* and then synthesize. In v1 that separation comes from the `ranges_over` answer read alongside the note's names, and the two Manns and the two Hinnebusches meet at the name they share rather than in a shared bucket.

> **STRUCK (D4, D9).** The single-cardinality rule, the required non-empty `polity` field, the `missing_polity` quarantine, and the many-valued `polities_touched` facet are retired with the tagging pass. Every polity a passage engages is now a **name** of `kind: country/state/place` in the interrogation's `names` answer (§7.15) — which was always the more honest shape, since a polity is a thing the corpus talks about, not an attribute of a paragraph. The per-polity coverage map the facet fed (`CHARTER.md` §3) is countable from name membership instead; wiring it is Phase B's, and the charter cross-reference is stale until then (Open Questions).

**`polity_canonical.yaml` survives, with a job (D9).** The canonical spelling map — aliases and historical polities folded to canonical referents — becomes the **seed for Reconcile's alias map** (§7.16). It is a cleanup aid, never a gate: an unmapped name always passes through and is reconciled on its merits, exactly as that file's own header has always said. Faithful naming at read time is untouched: the model names the true referent even when it is historical, defunct, or supra-national. `polity` rather than `country` was the right word for the same reason, and the `kind: country/state/place` name inherits it.

## Appendix F — Role-in-argument examples

`role:setup`, `role:claim`, `role:evidence`, `role:counter-position`, `role:synthesis`, `role:methodological`, `role:digression`.

In v1 these are examples for the `move` question (§7.15), and the reframe matters more here than anywhere else in these appendices.
